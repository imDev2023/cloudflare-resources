# Build > AI

Synthesis of the docs sidebar's Build > AI dropdown (Models, Workers AI, AI Gateway, Agents, Agent Memory, Wallets, Sandboxes, Vectorize, AI Search, Web Search API, AI Crawl Control) plus Agent Lee, from the developers.cloudflare.com mirror taken on 2026-10-05 (`raw/docs/`, sidebar in `raw/nav/home-sidebar.md`) and the related blog and press material in `raw/blog/` and `raw/external/`.
Everything here is stated as of 2026-10-05 unless a different date is given, and every fact block cites its source page.

## Summary

Cloudflare's AI stack is one binding and one gateway wrapped around a catalog of 233 models: 69 run on Cloudflare GPUs as Workers AI (`@cf/...`, billed in Neurons at $0.011 per 1,000 with 10,000 free per day) and 164 third-party models (Anthropic, OpenAI, Google, xAI and others) are proxied through AI Gateway, and `env.AI.run()` reaches all of them.
AI Gateway adds logging, caching, rate and spend limits, fallbacks, guardrails, Unified Billing credits (5% fee on purchases, no markup on provider prices), and, since 2026-09-30 in beta, x402 "Machine Payments" that let a US-based client pay for four open models from a stablecoin wallet.
The Agents SDK (`agents`, v0.20.0 is the only version the docs name) turns Durable Objects into stateful agents with SQL state, scheduling, WebSockets, workflows, human-in-the-loop, MCP servers and clients, and tools for Code Mode, Browser Run, Sandboxes, AI Search and payments.
Its payments tools implement x402 (Coinbase's HTTP 402 standard, USDC on Base, Ethereum, Solana and other networks, though every Cloudflare code sample uses Base) and MPP (the Machine Payments Protocol, with Stripe cards and a "tempo" stablecoin method), on both the seller side (`paidTool`, `x402-hono`, the x402-proxy and mpp-proxy templates) and the buyer side (`withX402Client`, `mppx`).
Cloudflare Wallets (Account Wallets and agent Virtual Wallets holding stablecoins under spending caps) has been announced, but only `cloudflare.pay` handle reservation exists, and no source names its chain or asset.
For retrieval, Vectorize (GA vector database, up to 1,536 dimensions) sits under AI Search (managed RAG, GA on 2026-10-01, billing from 2026-11-01, with a built-in MCP endpoint per instance), and the Web Search API (open beta) adds live search from Ceramic.ai, Exa or Linkup through AI Gateway.
Sandboxes run untrusted code either in Firecracker-isolated Linux containers driven from a Durable Object or in Dynamic Workers, and both keep credentials outside the sandbox.
Agent Memory (private beta, unbilled) is managed long-term memory, AI Crawl Control lets publishers allow, block or (in closed beta, through Stripe in USD) charge AI crawlers, and Agent Lee is the dashboard's beta AI assistant, which is built on the same primitives.

## Models

### What it is

"Models" (https://developers.cloudflare.com/ai/models/) is Cloudflare's unified AI model catalog, the first entry of the sidebar's Build > AI dropdown.
It lists every model reachable through Cloudflare in one place: models Cloudflare runs on its own GPUs (Workers AI, tagged "Cloudflare-hosted") and external provider models proxied through AI Gateway (tagged "Third-party").
The AI landing page describes the platform as "a unified platform for running AI models, whether hosted on Cloudflare infrastructure (Workers AI) or proxied through AI Gateway to external providers", and states it is "Available on all plans".
Source: https://developers.cloudflare.com/ai/ and https://developers.cloudflare.com/ai/models/

The catalog UI filters by Task Types, Capabilities, Providers and Authors, sorts "Newest first", and can compare up to three models side by side.
Each model has its own page with: the model id, capability tags, a "Model Info" table (context window, terms and license, request formats, pricing, flags such as Function calling, Batch, LoRA, Reasoning, Vision, Partner, Real-time, Zero data retention, Beta), Usage snippets (Workers binding TypeScript and curl), worked Examples, a Parameters reference, and "API Schemas (Raw)" (`schema-input.json` and `schema-output.json` next to each page).
Hosted LLM pages also link a no-login LLM Playground (for example `https://playground.ai.cloudflare.com/?model=@cf/meta/llama-3.3-70b-instruct-fp8-fast`).
Source: https://developers.cloudflare.com/ai/models/ and https://developers.cloudflare.com/ai/models/@cf/meta/llama-3.3-70b-instruct-fp8-fast/

The same 69 hosted models also have legacy-path pages under `https://developers.cloudflare.com/workers-ai/models/<name>/`; that page set ("Workers AI Models", "We found 69 models") points to the unified catalog for "more models, including external providers".
The two hosted lists match exactly (checked against the mirror, as of 2026-10-05).
Source: https://developers.cloudflare.com/workers-ai/models/

The `raw/docs/ai/` tree is 236 pages: the AI landing page, the "Related products" page, the catalog index, and 233 model pages; `https://developers.cloudflare.com/ai/llms.txt` lists the same 233 model ids (no page missing from either side, as of 2026-10-05).
The "Related products" page links Workers AI, AI Gateway, Agents, AI Search, Vectorize, AI Crawl Control, Browser Rendering (at `/browser-run/`), Agent Lee, Dynamic Workers and Sandboxes.
Source: https://developers.cloudflare.com/ai/llms.txt and https://developers.cloudflare.com/ai/related-products/

### How models are addressed

Model id formats, as printed on each model page (as of 2026-10-05):

- `@cf/<author>/<model>` for Cloudflare-hosted Workers AI models, for example `@cf/meta/llama-3.3-70b-instruct-fp8-fast`, `@cf/openai/gpt-oss-120b`, `@cf/zai-org/glm-5.3`.
- `<provider>/<model>` for third-party models proxied through AI Gateway, for example `anthropic/claude-opus-5.5`, `openai/gpt-5.5`, `google/gemini-3.1-pro`, `xai/grok-4.7`.
- The older `@hf/<author>/<model>` prefix appears only in deprecation notices (for example `@hf/meta-llama/meta-llama-3-8b-instruct`, deprecated May 30, 2026); no current catalog model uses it.

Source: https://developers.cloudflare.com/ai/models/ and https://developers.cloudflare.com/workers-ai/changelog/

**Workers binding (both hosted and third-party).**
Every model page, hosted or third-party, shows the same call shape on the `AI` binding:

```ts
// hosted model
const response = await env.AI.run("@cf/meta/llama-3.3-70b-instruct-fp8-fast", { messages });

// third-party model, same binding
const response = await env.AI.run('anthropic/claude-opus-5.5', {
  max_tokens: 1024,
  messages: [{ content: 'What are the three laws of thermodynamics?', role: 'user' }],
});
```

Source: https://developers.cloudflare.com/ai/models/@cf/meta/llama-3.3-70b-instruct-fp8-fast/ and https://developers.cloudflare.com/ai/models/anthropic/claude-opus-5.5/

The Unified Billing page states that `env.AI.run()` can "Call any model listed in the model catalog", "both Workers AI models and third-party models from providers like OpenAI, Anthropic, and Google", and that a gateway is selected in the third argument:

```ts
const resp = await env.AI.run(
  "openai/gpt-4.1-mini",
  { messages: [{ role: "user", content: "What is Cloudflare?" }] },
  { gateway: { id: "my-gateway" } },
);
```

Source: https://developers.cloudflare.com/ai-gateway/features/unified-billing/

**REST endpoints** (all under `https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID/`, authenticated with `Authorization: Bearer $CLOUDFLARE_API_TOKEN`), as shown on the model pages:

| Endpoint | Used by (model pages, as of 2026-10-05) | Body shape |
| --- | --- | --- |
| `ai/run/@cf/<author>/<model>` | 48 hosted model pages | model input directly, e.g. `{"messages":[...]}` |
| `ai/run` | 108 third-party pages (image, video, audio, speech, some LLMs) | `{"model":"google/veo-3.1","input":{...}}` |
| `ai/v1/chat/completions` | 35 third-party pages ("Chat Completions" request format) | OpenAI Chat Completions |
| `ai/v1/responses` | 20 third-party pages ("Responses" request format) | OpenAI Responses |
| `ai/v1/messages` | 14 third-party pages ("Anthropic Messages" request format) | Anthropic Messages |

21 hosted pages (mostly audio, image and Partner models) show only the binding snippet and no curl example.
Hosted LLM pages add that "Workers AI also supports OpenAI compatible API endpoints for `/v1/chat/completions` and `/v1/embeddings`".
Source: https://developers.cloudflare.com/ai/models/@cf/meta/llama-3.3-70b-instruct-fp8-fast/ and https://developers.cloudflare.com/ai/models/anthropic/claude-opus-5.5/ and https://developers.cloudflare.com/ai/models/google/veo-3.1/

```bash
curl https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID/ai/v1/messages \
  --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  --header "Content-Type: application/json" \
  --data '{"model":"anthropic/claude-opus-5.5","max_tokens":1024,"messages":[{"content":"Hi","role":"user"}]}'
```

Source: https://developers.cloudflare.com/ai/models/anthropic/claude-opus-5.5/

Third-party responses through `ai/run` include `"gatewayMetadata": {"keySource": "Unified"}`, showing the call was served with Cloudflare-managed credentials (Unified Billing).
Video models return a completed job with a result URL, for example `{"result":{"video":"https://...mp4"},"state":"Completed"}` for `google/veo-3.1`.
`xai/grok-voice` (task label "websocket") returns a `wss://api.x.ai/v1/realtime?model=grok-voice-latest` URL plus an ephemeral bearer token rather than audio.
Source: https://developers.cloudflare.com/ai/models/google/veo-3.1/ and https://developers.cloudflare.com/ai/models/xai/grok-voice/

**Credential precedence for third-party models** (AI Gateway): a provider key on the request is forwarded unchanged; otherwise a BYOK key stored under the `default` alias; otherwise Unified Billing with Cloudflare-managed credentials.
On Unified Billing endpoints (`env.AI.run()` or `/ai/v1/chat/completions`) only the `default` BYOK alias prevents fall-through to Unified Billing.
"Require provider credentials" (API: `byok_only: true`) or the per-request header `cf-aig-no-wholesale: true` blocks fallback to Unified Billing and returns HTTP 400 instead.
Source: https://developers.cloudflare.com/ai-gateway/features/unified-billing/

**Cloudflare's own decision model (Clef).**
`@cf/cloudflare/clef` (27B) and `@cf/cloudflare/clef-flash` (9B) take a `state` (text, JSON, images or video) and a schema of typed `questions` and return "a probability for every allowed option of every question".
Question types in the example are `noul` (yes/no probability), `choice` (pick one option with per-option probabilities) and `score` (probability-weighted ordinal score):

```ts
const response = await env.AI.run("@cf/cloudflare/clef", {
  model: "clef",
  state: "Checkout has been failing for every customer for the last hour.",
  questions: {
    urgent: { type: "noul", instructions: "Is this support request urgent?" },
    team: { type: "choice", instructions: "Which team should handle this request?",
      criteria: { billing: "Payments, invoices, and refunds", technical: "Outages, errors, and configuration", sales: "Plans and upgrades" } },
    severity: { type: "score", instructions: "How severe is the customer impact?",
      criteria: ["No impact", "Minor", "Major", "Critical"] },
  },
});
```

## Workers AI

### What it is

Workers AI runs machine learning models on serverless GPUs across Cloudflare's network, so you pay only for what you use and never manage, scale or rent GPUs.
You call models from Workers, Pages (Pages Functions), or from anywhere through the Cloudflare REST API.
It is available on both the Free and Paid Workers plans.
Customers with custom requirements (private custom models, higher limits) are pointed to a Custom Requirements Form (https://forms.gle/axnnpGDb6xrmR31T6).
Source: https://developers.cloudflare.com/workers-ai/

Workers AI is one half of the unified "Cloudflare AI" platform: the AI landing page describes models "hosted on Cloudflare infrastructure (Workers AI) or proxied through AI Gateway to external providers".
The sidebar's Models entry (https://developers.cloudflare.com/ai/models/) is the unified catalog of both kinds; it reports 233 models as of 2026-10-05, while the Workers AI catalog (https://developers.cloudflare.com/workers-ai/models/) reports 69 Cloudflare-hosted models as of 2026-10-05.
The Workers AI catalog page itself links out with "Looking for more models, including external providers? Check out the unified AI model catalog".
Sources: https://developers.cloudflare.com/ai/ , https://developers.cloudflare.com/ai/models/ , https://developers.cloudflare.com/workers-ai/models/

Since 2026-08-07, Workers AI and AI Gateway share one access path: the same AI binding (`env.AI.run()`) and the same REST `/ai/` endpoints call both Workers AI models (`@cf/...`) and supported third-party models (`{author}/{model}`), with AI Gateway providing observability, logging, caching, security and billing controls.
Source: https://developers.cloudflare.com/changelog/post/2026-08-07-workers-ai-unified-billing/

### Key concepts

- **Model ids.** Models are addressed by a prefixed id: `@cf/<author>/<model>` for Cloudflare-hosted models and `@hf/<author>/<model>` for older Hugging Face TGI-served models (for example `@hf/mistral/mistral-7b-instruct-v0.2`); third-party models via AI Gateway use `{author}/{model}` such as `openai/gpt-4.1-mini` (https://developers.cloudflare.com/workers-ai/models/ , https://developers.cloudflare.com/ai-gateway/usage/worker-binding-methods/).
- **Task types.** The catalog filters by task: Text Generation, Text Embeddings, Text Classification (including reranking), Text-to-Image, Image-to-Text, Image Classification, Object Detection, Automatic Speech Recognition, Text-to-Speech, Translation, Summarization, and a "Dumb Pipe" task used by `@cf/pipecat-ai/smart-turn-v2` (https://developers.cloudflare.com/workers-ai/models/ , https://developers.cloudflare.com/workers-ai/platform/limits/).
- **Capability tags.** Model pages tag Cloudflare-hosted, Batch, Function calling, Reasoning, Vision, LoRA, Partner and Real-time (https://developers.cloudflare.com/workers-ai/models/).
- **Partner models.** Since 2025-08-27 the catalog includes partner models (Deepgram Aura and Nova, Leonardo Lucid Origin and Phoenix, Black Forest Labs FLUX.2), and audio models gained WebSocket support (https://developers.cloudflare.com/workers-ai/changelog/).
- **Neurons.** Neurons measure "the GPU compute needed to perform your request"; pricing is shown per model in units (tokens, tiles, audio minutes) but still billed in neurons in the back end (https://developers.cloudflare.com/workers-ai/platform/pricing/).
- **Context window.** The sum of input, reasoning and completion tokens a model supports; `max_tokens` cannot exceed it, and a request whose prompt plus response exceeds it errors (https://developers.cloudflare.com/workers-ai/platform/glossary/ , https://developers.cloudflare.com/workers-ai/changelog/).
- **Scoped vs unscoped prompts.** Scoped prompts are a `messages` array with `system`, `user` and `assistant` roles, and Workers AI applies the right chat template per model (the recommended method); unscoped prompts send a single `prompt` string, and `raw: true` lets you hand-write the model's chat template; unscoped prompts are recommended for LoRA inference (https://developers.cloudflare.com/workers-ai/features/prompting/).
- **Model license gating.** Some models require accepting a license by sending a first request with `"prompt": "agree"`, for example `@cf/meta/llama-3.2-11b-vision-instruct`; otherwise error `5016` "User has not agreed to Llama3.2 model terms" is returned (https://developers.cloudflare.com/workers-ai/models/llama-3.2-11b-vision-instruct/ , https://developers.cloudflare.com/workers-ai/platform/errors/).
- **Paid-only models.** Some frontier models are not available through Workers Free billing and require the Workers Paid plan or prepaid AI Gateway credits (listed under Pricing below) (https://developers.cloudflare.com/workers-ai/platform/pricing/).
- **Local development is not free.** "Using Workers AI always accesses your Cloudflare account in order to run AI models and will incur usage charges even in local development", and local-mode inferences count toward rate limits (https://developers.cloudflare.com/workers-ai/get-started/workers-wrangler/ , https://developers.cloudflare.com/workers-ai/platform/limits/).

#### Function calling (traditional)

Pass an OpenAI-style `tools` array (name, description, JSON-schema `parameters`) to a model tagged Function calling.
The model returns `tool_calls` (name plus arguments); you execute the call and send the result back as a `tool` role message.
Tool-capable models in the catalog as of 2026-10-05 include `@cf/moonshotai/kimi-k2.6`, `@cf/moonshotai/kimi-k2.7-code`, `@cf/zai-org/glm-5.2`, `@cf/zai-org/glm-5.3`, `@cf/zai-org/glm-5.3-flash`, `@cf/zai-org/glm-4.7-flash`, `@cf/deepseek-ai/deepseek-v4-flash-0731`, `@cf/deepseek-ai/deepseek-v4-pro-0813`, `@cf/openai/gpt-oss-120b`, `@cf/openai/gpt-oss-20b`, `@cf/google/gemma-4-26b-a4b-it`, `@cf/qwen/qwen3.8-27b`, `@cf/qwen/qwen3-30b-a3b-fp8`, `@cf/nvidia/nemotron-3-120b-a12b`, `@cf/meta/llama-4-scout-17b-16e-instruct`, `@cf/meta/llama-3.3-70b-instruct-fp8-fast`, `@cf/mistralai/mistral-small-3.1-24b-instruct`, `@cf/ibm-granite/granite-4.0-h-micro`, `@cf/utter-project/eurollm-9b-it` and `@cf/swiss-ai/apertus-v1.5-8b` (per each model page's tags).

#### Function calling (embedded)

Embedded function calling runs your tool code alongside inference inside the Worker, using `@cloudflare/ai-utils` (open source at https://github.com/cloudflare/ai-utils).
`runWithTools(env.AI, model, { messages, tools }, config)` loops model call, function execution and final answer for you; each tool carries a `function` reference.
Config options: `streamFinalResponse`, `maxRecursiveToolRuns`, `strictValidation`, `verbose`, `trimFunction` (pass `autoTrimTools` to have an LLM pre-select relevant tools and save input tokens).
`createToolsFromOpenAPISpec(spec, { overrides, matchPatterns })` turns a JSON or YAML OpenAPI spec (or its URL) into tools, with header overrides for auth or User-Agent.
It works only from Workers, not from the REST API.
Billing is normal inference plus normal Worker CPU time for the tool code.
For a `BadInput` error the troubleshooting page says inputs may exceed the model's context window.
Documented examples: `fetch()` to an external API, KV storage, and OpenAPI-generated tools.
Sources: https://developers.cloudflare.com/workers-ai/features/function-calling/ , https://developers.cloudflare.com/workers-ai/features/function-calling/embedded/ , https://developers.cloudflare.com/workers-ai/features/function-calling/embedded/api-reference/ , https://developers.cloudflare.com/workers-ai/features/function-calling/embedded/get-started/ , https://developers.cloudflare.com/workers-ai/features/function-calling/embedded/troubleshooting/

```js
import { runWithTools } from "@cloudflare/ai-utils";
const sum = (args) => Promise.resolve((args.a + args.b).toString());
const response = await runWithTools(env.AI, "@hf/nousresearch/hermes-2-pro-mistral-7b", {
	messages: [{ role: "user", content: "What the result of 123123123 + 10343030?" }],
	tools: [{
		name: "sum",
		description: "Sum up two numbers and returns the result",
		parameters: { type: "object", properties: { a: { type: "number" }, b: { type: "number" } }, required: ["a", "b"] },
		function: sum,
	}],
});
```

Source: https://developers.cloudflare.com/workers-ai/features/function-calling/embedded/get-started/ (note that the model used in this official example was deprecated on 2026-05-30; see Gaps below).

#### Asynchronous Batch API

Send many inference requests in one call; the API returns `{ status: "queued", request_id, model }` immediately, and you poll with `{ request_id }` until it returns `responses[]` (each with `id` matching the input index, `result`, `success` and your optional `external_reference`) plus `usage`.
Batching "will guarantee that your requests are fulfilled eventually, rather than erroring out if Cloudflare does not have enough capacity".
Total payload must be under 10 MB.
Binding: pass `{ queueRequest: true }` as the third argument; REST: append `?queueRequest=true` to `/ai/run/{model}`.
Supported models carry the Batch tag (catalog filter `?capabilities=Batch`); as of 2026-10-05 these include the Deepgram Aura and Nova models, bge-base/large/small embeddings, Kimi K2.6, DeepSeek V4 Flash, gpt-oss-120b and 20b, Gemma 4 26B, Qwen3.8 27B, Qwen3 30B, Llama 4 Scout, Llama 3.3 70B fp8-fast, m2m100, smart-turn-v2 and whisper-large-v3-turbo.
The batch system was redesigned on 2026-03-19 as a pull-based system that processes queued requests as capacity frees up.
A template repo exists at https://github.com/craigsdennis/batch-please-workers-ai.
Sources: https://developers.cloudflare.com/workers-ai/features/batch-api/ , https://developers.cloudflare.com/workers-ai/features/batch-api/workers-binding/ , https://developers.cloudflare.com/workers-ai/features/batch-api/rest-api/ , https://developers.cloudflare.com/workers-ai/changelog/

```ts
const queued = await env.AI.run("@cf/baai/bge-m3",
	{ requests: [{ query: "This is a story about Cloudflare", contexts: [{ text: "..." }] }] },
	{ queueRequest: true });
const status = await env.AI.run("@cf/baai/bge-m3", { request_id: "000-000-000" });
```

Source: https://developers.cloudflare.com/workers-ai/features/batch-api/workers-binding/

#### Event subscriptions

Workers AI publishes batch lifecycle events to a Cloudflare Queue: `cf.workersAi.model.batch.queued`, `cf.workersAi.model.batch.succeeded` and `cf.workersAi.model.batch.failed` (the failure payload carries `message`, `internalCode`, `httpCode`).
Each event carries `requestId`, `modelName`, `accountId` and an `eventTimestamp`.
This lets you consume batch completion from a Queue consumer Worker or HTTP pull consumer instead of polling.
Source: https://developers.cloudflare.com/workers-ai/platform/event-subscriptions/

#### Prompt caching (prefix caching)

Workers AI caches computed prefill tensors and reuses them when a later request shares the same token prefix, cutting time to first token and cost.
It is on by default for select models, and cached input tokens are billed at a discount, shown per model (for example Kimi K2.6 at $0.16 per M cached input tokens versus $0.95 uncached, as of 2026-10-05).
Hits require routing to the same model instance, so send `x-session-affinity: <session id>` (REST header, or `extraHeaders` in the binding's third argument).
Put static content (system prompt, tool definitions) first, keep tool definitions stable, and never put timestamps at the start of the system prompt.
Cached counts appear in the response `usage` object; first requests are cold, and inputs must be large enough to fill a cache block.
Sources: https://developers.cloudflare.com/workers-ai/features/prompt-caching/ , https://developers.cloudflare.com/workers-ai/platform/pricing/

```js
const response = await env.AI.run("@cf/moonshotai/kimi-k2.5", { messages }, {
	extraHeaders: { "x-session-affinity": "ses_12345678" },
});
```

Source: https://developers.cloudflare.com/workers-ai/features/prompt-caching/

#### Reject busy requests

Set `rejectIfBusy` so a synchronous request fails instead of waiting in a capacity queue: REST `"options": { "rejectIfBusy": true }` in the body, binding `{ rejectIfBusy: true }` as the third argument (never inside the model input), Chat Completions as a top-level `options` field.
Rejected requests return HTTP `429` with internal code `3040` and the message `Capacity temporarily exceeded, please try again.`
Source: https://developers.cloudflare.com/workers-ai/features/reject-if-busy/

#### Fine-tunes with LoRA adapters

Workers AI runs inference with LoRA adapters on top of LoRA-capable base models (catalog filter `?capabilities=LoRA`; non-quantized bases only).
Constraints as of 2026-10-05: adapter file under 300 MB, files named exactly `adapter_model.safetensors` and `adapter_config.json`, `model_type` in the config set to one of `mistral`, `gemma` or `llama`, and up to 100 adapters per account.
Assets cannot be edited after upload; create a new fine-tune instead.
Upload with `npx wrangler ai finetune create <model_name> <finetune_name> <folder_path>` (list with `npx wrangler ai finetune list`) or the REST endpoints `/ai/finetunes` and `/ai/finetunes/{id}/finetune-assets/` (token permission `Workers AI Write`).

Public adapters named `cf-public-*` (`cf-public-magicoder`, `cf-public-jigsaw-classification`, `cf-public-cnn-summarization`) are listed at `/ai/finetunes/public`.

#### Markdown Conversion (`toMarkdown`)

`env.AI.toMarkdown(files, { conversionOptions })` or `POST /ai/tomarkdown` (multipart `files` plus a `conversionOptions` form field) converts documents to Markdown for RAG and LLM input.
Supported formats as of 2026-10-05: PDF, images (jpeg, jpg, png, webp, svg, gif, bmp), HTML, XML, Office (xlsx, xlsm, xlsb, xls, et, docx), OpenDocument (ods, odt), CSV and Apple `.numbers`; `.docx` and `.odt` were added on 2025-09-23.
Each `ConversionResult` has `id`, `name`, `format` (`markdown`, `text` or `error`), `mimetype`, `tokens`, and `data` or `error`.
`env.AI.toMarkdown().supported()` lists formats; `.transform()` is an alternate handle with the same signature.
Options: `output.format` (`markdown` or `text`), `image.descriptionLanguage` (en, it, de, es, fr, pt; best effort), `html.hostname` and `html.cssSelector`, `pdf.metadata` (opt out of metadata).
HTML pre-processing drops `script` and `style`, extracts title, description, Open Graph and JSON-LD, and removes header, footer and head unless a `cssSelector` is given.
Images over 1280x720 are resized, run through `@cf/facebook/detr-resnet-50` object detection, then described by `@cf/google/gemma-4-26b-a4b-it`; animated GIFs use only the first frame, and SVGs are rasterised to PNG.
PDFs are parsed page by page, using the PDF/UA `StructTree` for semantic Markdown when present and raw text otherwise.
Pricing: free for most formats, but image conversion uses Workers AI models that bill against the neuron allocation.
Related features outside Workers AI: Browser Run's `/markdown` endpoint renders dynamic pages first, and "Markdown for Agents" converts zone content on the fly via content negotiation.
Sources: https://developers.cloudflare.com/workers-ai/features/markdown-conversion/ , https://developers.cloudflare.com/workers-ai/features/markdown-conversion/supported-formats/ , https://developers.cloudflare.com/workers-ai/features/markdown-conversion/how-it-works/ , https://developers.cloudflare.com/workers-ai/features/markdown-conversion/conversion-options/ , https://developers.cloudflare.com/workers-ai/features/markdown-conversion/usage/binding/ , https://developers.cloudflare.com/workers-ai/features/markdown-conversion/usage/rest-api/ , https://developers.cloudflare.com/workers-ai/changelog/

#### Decision models (Clef)

`@cf/cloudflare/clef` (27B, multimodal, 65,536-token context) and `@cf/cloudflare/clef-flash` are the first models trained by the Workers AI team, released 2026-10-01 with Apache 2.0 weights on Hugging Face.
Instead of free text, Clef takes a state (text, JSON, images or video) and a schema of typed questions (up to 64 per request) and returns a probability for every allowed answer, so an agent can route, block or escalate without parsing prose.
It follows Typesafe's "System One API", so a Jev integration can switch by changing endpoint and model; Cloudflare's own benchmarks claim Clef is 2.5x faster than Jev at the median and Clef-flash 13x faster.
Pricing as of 2026-10-05: Clef $0.24 per M input tokens, Clef-flash $0.09 per M input tokens.
Sources: https://developers.cloudflare.com/changelog/post/2026-10-01-clef-workers-ai/ , https://developers.cloudflare.com/workers-ai/models/clef/ , https://developers.cloudflare.com/workers-ai/platform/pricing/

## AI Gateway

### What it is

AI Gateway is a proxy that sits between an application and AI model providers, giving visibility (analytics, logging) and control (caching, rate limiting, request retries, model fallback) over AI traffic.
Cloudflare describes it as "Observe and control your AI applications" and says it takes one line of code to start.
It is "Available on all plans".
Source: https://developers.cloudflare.com/ai-gateway/

As of 2026-10-05 it is also the front door for all model calls on Cloudflare: Workers AI models (`@cf/...`) and third-party models (`openai/...`, `anthropic/...`, `google/...`) are called through the same AI binding (`env.AI.run()`) and the same REST API (`api.cloudflare.com/.../ai/...`), with AI Gateway providing observability, logging, caching, security and billing controls.
This unification shipped on 2026-08-07 ("Workers AI and AI Gateway unify model access and billing").
Source: https://developers.cloudflare.com/ai-gateway/changelog/

It also carries Cloudflare's newer AI-commerce and search features: Unified Billing (prepaid credits for every provider), Machine Payments (x402 stablecoin payment per inference call, beta), Auto Router (`cloudflare/auto`), and the Web Search API (beta, billed to AI Gateway credits).
Sources: https://developers.cloudflare.com/ai-gateway/features/unified-billing/, https://developers.cloudflare.com/ai-gateway/features/machine-payments/, https://developers.cloudflare.com/ai-gateway/features/auto-router/, https://developers.cloudflare.com/ai-gateway/changelog/

### Key concepts

- **Gateway**: a named configuration object (name up to 64 characters) holding settings for caching, rate limiting, logging, authentication, retries, DLP, Guardrails, spend limits, BYOK keys, dynamic routes, custom domains and Workers AI billing mode.
  Source: https://developers.cloudflare.com/ai-gateway/configuration/manage-gateway/
- **Default gateway**: if a request omits the gateway ID, AI Gateway uses the ID `default`, and creates it on the first authenticated request if it does not exist.
  Auto-creation applies only to the ID `default`.
  The auto-created gateway has authentication On, log collection On, caching Off (TTL 0), rate limiting Off, Require provider credentials Off, and Workers AI billing set to Standard billing.
  Deleting it and sending a new authenticated request recreates it.
  Source: https://developers.cloudflare.com/ai-gateway/configuration/manage-gateway/
- **Workers AI requests always need the gateway named**: third-party model calls default to `default`, but Workers AI (`@cf/`) calls over the REST API require the `cf-aig-gateway-id` header.
  Source: https://developers.cloudflare.com/ai-gateway/get-started/
- **Model naming**: third-party models use `author/model` (for example `openai/gpt-4.1`, `anthropic/claude-sonnet-4`, `google/gemini-3-flash`, `xai/grok-3`); Workers AI models use `@cf/author/model` (for example `@cf/moonshotai/kimi-k2.6`).
  Source: https://developers.cloudflare.com/ai-gateway/usage/rest-api/
- **Credential precedence** (how the upstream provider is paid):
  1. A provider key on the request (for example an `Authorization` header) is forwarded unchanged, and BYOK and Unified Billing are not consulted.
  2. Otherwise a BYOK key stored under the `default` alias is used.
  3. Otherwise the request uses Cloudflare-managed credentials and is billed against the Unified Billing credit balance.
  On Unified Billing paths (`env.AI.run()`, `/ai/v1/chat/completions`) only the `default` BYOK alias is consulted; other aliases are ignored and the request falls through to Unified Billing.
  The `cf-aig-byok-alias` header selects a non-default alias only on provider-native passthrough requests.
  Source: https://developers.cloudflare.com/ai-gateway/features/unified-billing/
- **Configuration hierarchy**: request-level headers override gateway-level settings.
  Some restrictive settings are additive: `cf-aig-no-wholesale` can require provider credentials on one request but cannot turn off the gateway's **Require provider credentials** setting.
  Source: https://developers.cloudflare.com/ai-gateway/glossary/
  On the deprecated Universal Endpoint there is a third level: provider-level headers override request-level headers, which override gateway settings.
  Source: https://developers.cloudflare.com/ai-gateway/usage/universal/
- **Workers AI billing mode** per gateway: **Standard billing** (charged at the end of the billing cycle) or **Unified billing** (deducted in real time from prepaid AI Gateway credits).
  Source: https://developers.cloudflare.com/ai-gateway/configuration/manage-gateway/

### API and binding surface

#### Endpoint families

There are two endpoint families, plus WebSockets and the Workers binding.

1. **Cloudflare REST API** at `https://api.cloudflare.com/client/v4/accounts/{account_id}/ai/...`, authenticated with a Cloudflare API token in the standard `Authorization` header.
   Recommended for new integrations.
   Source: https://developers.cloudflare.com/ai-gateway/configuration/authentication/

| Endpoint | Format | Use case | Third-party models | Workers AI models (`@cf/`) |
| --- | --- | --- | --- | --- |
| `POST /ai/run` | Envelope with `model`, `input` (and optional `options`) | All models and modalities (LLM, image, TTS, ASR) | Yes | Yes |
| `POST /ai/v1/chat/completions` | OpenAI chat completions | LLMs, OpenAI SDK compatible | Yes | Yes |
| `POST /ai/v1/responses` | OpenAI Responses API | Agentic workflows, OpenAI SDK compatible | Yes | Model dependent (for example GPT-OSS) |
| `POST /ai/v1/messages` | Anthropic Messages API | LLMs, Anthropic SDK compatible | Yes | No |

The older Workers AI path with the model in the URL (`/ai/run/@cf/{model}`) still works, and is the path the docs give for paying Workers AI with prepaid credits (with the gateway set to Unified billing and named in `cf-aig-gateway-id`).
The REST API token needs **Account > Workers AI > Read**; all `/accounts/{account_id}/ai/*` endpoints require the Workers AI permission, even for third-party models, and a token holding only an AI Gateway permission returns `401` with error code `10000`.
The `AI Gateway` permissions apply to `/accounts/{account_id}/ai-gateway/*` (gateway configuration, logs, routes).
Source: https://developers.cloudflare.com/ai-gateway/usage/rest-api/

```bash
curl -X POST "https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID/ai/run" \
  --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  --header "cf-aig-gateway-id: default" \
  --header "Content-Type: application/json" \
  --data '{"model": "@cf/moonshotai/kimi-k2.6",
           "input": {"messages": [{"role": "user", "content": "What is Cloudflare?"}]}}'
```

OpenAI and Anthropic SDKs work by pointing `baseURL` at `https://api.cloudflare.com/client/v4/accounts/${ACCOUNT_ID}/ai/v1` with the Cloudflare API token as the API key; the gateway can be set with `defaultHeaders: { "cf-aig-gateway-id": "..." }`.

### Features

#### Unified Billing (credits)

Load prepaid credits in the dashboard (**AI Gateway > Credits Available > Manage > Top-up credits**), optionally with auto top-up at a threshold, and pay Workers AI and third-party providers on one Cloudflare bill without provider keys.
A 5% fee applies to credit purchases ($100 of credit costs $105), and provider inference prices are passed through with no markup (as of 2026-10-05).
The balance can occasionally go negative; Cloudflare then charges the payment method on file at the start of the next month.
Turning on **Require provider credentials** (`byok_only: true`) makes third-party requests without supplied or stored credentials return `400` instead of falling back to Unified Billing; Workers AI requests are unaffected.
Zero Data Retention (ZDR) routes Unified Billing traffic to provider endpoints that do not retain prompts or responses; it applies only to Cloudflare-managed-credential requests, not BYOK, and does not change AI Gateway's own logging; per-model ZDR support is listed in the model catalog.
Provider-native endpoints that accept Unified Billing: OpenAI, Anthropic, Google AI Studio, Google Vertex AI, xAI, Groq.
Unified Billing requests are limited to 200 requests per 60 seconds per gateway (BYOK requests are not).
Prepaid credits unlock Workers AI frontier models without the Workers Paid plan and raise their limit to 50 requests per minute per account per model, versus 20 per minute through standard Workers AI billing (models named on 2026-08-07: `@cf/moonshotai/kimi-k2.6`, `@cf/moonshotai/kimi-k2.7-code`, `@cf/zai-org/glm-5.2`).
Since 2026-09-01 monthly usage invoices show one total per model under a standardized `provider/model` name.
Sources: https://developers.cloudflare.com/ai-gateway/features/unified-billing/, https://developers.cloudflare.com/ai-gateway/reference/limits/, https://developers.cloudflare.com/ai-gateway/changelog/

#### Machine Payments (x402)

Machine Payments lets a client pay for inference calls to select open models from a stablecoin wallet instead of keeping a prepaid credit balance.
Requirements: the customer must be based in the United States, have a credit card on file, and use an authenticated gateway with a Cloudflare API token.
Status: beta since 2026-09-30.
Eligible endpoint (as of 2026-10-05): only `POST /ai/run`.
Eligible models (as of 2026-10-05): `z-ai/glm-4.7-flash`, `google/gemma-4-26b-a4b-it`, `openai/gpt-oss-20b`, `alibaba/qwen3.8-27b`.
Flow:
1. The client sends the inference request with the Cloudflare-specific `Payment-Method: x402` header.
2. AI Gateway returns `402 Payment Required` with a standard base64 `PAYMENT-REQUIRED` header listing accepted network, asset, payment scheme and maximum authorized amount; most models use the `upto` scheme (a ceiling, not an exact price).
3. The wallet signs an authorization for up to the maximum.
4. The client retries with the standard `PAYMENT-SIGNATURE` header.
5. Cloudflare verifies, runs the inference, and settles the actual cost, which cannot exceed the authorized maximum.
Without `Payment-Method: x402`, normal credential precedence applies and the cost may be deducted from Unified Billing credits.
The x402 protocol link points to https://github.com/x402-foundation/x402.
The AI Gateway pages do not name which blockchain networks or stablecoin assets are accepted; those are only stated as being inside the `PAYMENT-REQUIRED` header.

```bash
curl -iX POST "https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID/ai/run" \
  --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  --header "Payment-Method: x402" \
  --header "Content-Type: application/json" \
  --data '{"model": "z-ai/glm-4.7-flash",
           "input": {"max_tokens": 9001, "messages": [{"role": "user", "content": "What is Cloudflare?"}]}}'
```

Sources: https://developers.cloudflare.com/ai-gateway/features/machine-payments/, https://developers.cloudflare.com/ai-gateway/changelog/

#### Caching

Caching is off by default; turn it on per gateway (dashboard **Settings > Cache Responses**, or `cache_ttl` via the API).
Only text and image responses are cached, and only for identical requests; semantic caching is described as future work.
The default cache key is a SHA-256 hash of provider, endpoint, model, provider authentication header and full request body.
Per request: `cf-aig-skip-cache`, `cf-aig-cache-ttl` (minimum 60 seconds, maximum one month), `cf-aig-cache-key` (overrides the key and opts the request in; TTL falls back to the gateway default, else 5 minutes).
The cache is volatile: two simultaneous identical requests may both reach the provider.
Streaming responses are not cached by default.
Cache hits cost `0` even when a custom cost is set.
Limit: 25 MB cacheable request size.
Sources: https://developers.cloudflare.com/ai-gateway/features/caching/, https://developers.cloudflare.com/ai-gateway/reference/troubleshooting/, https://developers.cloudflare.com/ai-gateway/configuration/custom-costs/, https://developers.cloudflare.com/ai-gateway/reference/limits/

#### Rate limiting

Per-gateway request-count limit (for example 100 requests per 60 seconds) with a **fixed** or **sliding** window; exceeding it returns `429 Too Many Requests`.
API fields: `rate_limiting_interval`, `rate_limiting_limit`, `rate_limiting_technique`.
Source: https://developers.cloudflare.com/ai-gateway/features/rate-limiting/

#### Spend limits

Cost-based budgets (in dollars) over a rolling or fixed window; when any applicable rule is over budget the request is blocked with `429` until the window resets.
Rules can be scoped by provider, model and custom metadata keys, each dimension either **Split by value** (separate bucket per value, for example per `agent_id`) or **Filter by value** (applies only to one value).
With Cloudflare Access in front of the gateway, the reserved metadata key `cf.user_id` gives per-user budgets without client changes.
Instead of blocking, a dynamic route with a cheaper fallback model can absorb overflow.
Spend limits work for Unified Billing and BYOK requests for models with known pricing; they are eventually consistent, so concurrent bursts can briefly overshoot; cost tracking is a best-effort estimate.
Limit: 20 rules per gateway.
Sources: https://developers.cloudflare.com/ai-gateway/features/spend-limits/, https://developers.cloudflare.com/ai-gateway/changelog/

#### Request handling: timeouts, retries, fallbacks

Timeouts (`cf-aig-request-timeout`, ms) count until the first part of the response arrives.
Retries: up to 5 attempts, delay up to 60 seconds, backoff constant, linear or exponential; the final attempt waits indefinitely.
Gateway-level automatic retries (since 2026-04-02) are configured under **Settings > Retry Requests** and per-request headers override them.
Fallbacks across providers are done with Dynamic Routing (current) or the array form of the deprecated Universal Endpoint, with `cf-aig-step` reporting which step answered.
Sources: https://developers.cloudflare.com/ai-gateway/configuration/request-handling/, https://developers.cloudflare.com/ai-gateway/configuration/manage-gateway/, https://developers.cloudflare.com/ai-gateway/configuration/fallbacks/

#### Dynamic routing

A route is a named, versioned flow (called as model `dynamic/{route}`) built in a visual editor or as JSON via the REST API, with instant rollback between versions.
Node types: Start, Conditional (MongoDB-like operators `$eq`, `$ne`, `$in`, `$and`, `$or` over body, headers or `metadata.*`), Percentage (up to 5 outputs summing to 100%), Rate/Budget limit (`limitType` `count` or `cost`, `key` such as `metadata.user_id`, `limit`, `window` in seconds, optional `fallback` output), Model (`provider`, `model`, `timeout`, `retries`, optional `fallback` output), End.
Routes accept only the OpenAI chat completions request shape (other formats return `400`) and are scoped to one gateway (wrong gateway returns `404`).
The docs say to turn on authentication and store provider keys with BYOK before using routes.
Sources: https://developers.cloudflare.com/ai-gateway/features/dynamic-routing/, https://developers.cloudflare.com/ai-gateway/features/dynamic-routing/json-configuration/, https://developers.cloudflare.com/ai-gateway/features/dynamic-routing/usage/

```json
{ "id": "<id>", "type": "rate",
  "properties": { "limitType": "count", "key": "metadata.user_id", "limit": 100, "window": 3600 },
  "outputs": { "success": { "elementId": "node_model_workers_ai" }, "fallback": { "elementId": "node_model_openai_mini" } } }
```

#### Auto Router

Send model `cloudflare/auto` (Chat Completions or Responses format; WebSockets not yet supported) and AI Gateway picks a model per request.
It builds a pool of eligible models (input support, credentials, billing, spend limits, provider health), classifies task type and difficulty, scores quality against cost, tries the top model and falls back to the next.
Session affinity via `cf-aig-session-id` keeps one model per turn so prompt caching works; `cf-aig-turn-id` marks turns; `cf-aig-no-session-affinity: true` disables it.
`cf-aig-allowed-models` (supports `*`, which does not match `/`, so use `anthropic/*`) and `cf-aig-allowed-providers` restrict the pool; an entry matching nothing returns `400`.
Routing reasons: `cost_optimal_within_pool`, `forced_by_candidate_pool`, `pinned_by_turn`, `fallback_candidate_unavailable`, `fallback_key_not_in_candidates`, `fallback_router_error`, `fallback_router_timeout`, `fallback_unsupported_input`.
Default pool as of 2026-10-05: `anthropic/claude-fable-5`, `anthropic/claude-opus-5`, `anthropic/claude-sonnet-5`, `openai/gpt-5.6-luna`, `openai/gpt-5.6-sol`, `openai/gpt-5.6-terra`, `xai/grok-4.5`.
Additional opt-in models as of 2026-10-05 include Workers AI `@cf/deepseek-ai/deepseek-v4-flash-0731`, `@cf/deepseek-ai/deepseek-v4-pro-0813`, `@cf/google/gemma-4-26b-a4b-it`, `@cf/moonshotai/kimi-k2.7-code`, `@cf/openai/gpt-oss-20b`, `@cf/qwen/qwen3.8-27b`, `@cf/zai-org/glm-5.2`, plus `alibaba/qwen3.8-max`, `anthropic/claude-fable-5.1`, `anthropic/claude-opus-4.8`, `anthropic/claude-opus-5.5`, `anthropic/claude-sonnet-4.6`, `fireworks/glm-5.3`, `fireworks/glm-5.3-flash`, `minimax/m3`, `openai/gpt-5.5`, `openai/gpt-6-astra`, `openai/gpt-6-luna`, `openai/gpt-6-sol`, `xai/grok-4.6`.
An OpenCode config and the `@cloudflare/aig-opencode-plugin` (OpenCode 1.18.29 or later) expose Auto Router in that coding agent.
Source: https://developers.cloudflare.com/ai-gateway/features/auto-router/

#### Guardrails

Content moderation of prompts and responses across all providers, configured per gateway as **Flag**, **Ignore** or **Block** per hazard category (API accepts `FLAG` and `BLOCK`; omitting a category means Ignore).
Categories `S1` to `S13` (Violent Crimes, Non-Violent Crimes, Sex-Related Crimes, Child Sexual Exploitation, Defamation, Specialized Advice, Privacy, Intellectual Property, Indiscriminate Weapons, Hate, Suicide and Self-Harm, Sexual Content, Elections) are evaluated with `@cf/meta/llama-guard-3-8b`; Llama Guard's `S14` (code interpreter abuse) is not evaluated; `P1` (prompt injection) uses `@cf/meta/prompt-guard-2-86m`.
Blocked prompt returns error code `2016`, blocked response `2017`.
Typical added latency is about 500 ms per request; long content is chunked; supported languages are English, French, German, Hindi, Italian, Portuguese, Spanish and Thai.
If any category is set to block and Workers AI cannot be reached, the request is blocked; if only flag, it proceeds unevaluated.
Streaming is not supported: on the REST API the response is evaluated and logged but not enforced; on gateway endpoints the response is buffered and returned non-streamed.
Embedding and unknown model types get prompt-only evaluation.
Guardrails usage is billed as Workers AI inference.
Sources: https://developers.cloudflare.com/ai-gateway/features/guardrails/, https://developers.cloudflare.com/ai-gateway/features/guardrails/set-up-guardrail/, https://developers.cloudflare.com/ai-gateway/features/guardrails/usage-considerations/, https://developers.cloudflare.com/ai-gateway/features/guardrails/supported-model-types/, https://developers.cloudflare.com/ai-gateway/reference/pricing/

#### Data Loss Prevention (DLP)

Scans prompts and/or responses (per policy **Check**: Request, Response or Both) against Cloudflare One DLP profiles shared at account level, with action **Flag** or **Block**; turned on under the gateway's **Firewall** tab or via the `dlp` object on the gateway.
No Gateway proxy or TLS decryption is needed, policies are per gateway, events appear in AI Gateway logs, and there is no per-request header to bypass or select profiles (use separate gateways for different policies).
Only raw body text is scanned (no base64 decoding, no URL following, no binary multipart parts); tool-call arguments and results in the JSON body are scanned.
Response scanning buffers streamed responses, raising time-to-first-token; request-only scanning does not.
Blocked responses are not cached; cache hits skip DLP and are not re-evaluated after policy changes.
Errors: `2029` (request blocked) and `2030` (response blocked), with the `cf-aig-dlp` header describing findings.
Sources: https://developers.cloudflare.com/ai-gateway/features/dlp/, https://developers.cloudflare.com/ai-gateway/features/dlp/set-up-dlp/

#### Authentication, BYOK, custom domains and Access

- **Authenticated Gateway**: requires a Cloudflare API token on each request (`Authorization` on the REST API, `cf-aig-authorization` on gateway endpoints); create the token from gateway settings with `Run` permission and toggle Authenticated Gateway on.

## Agents

### What it is

The Agents SDK (npm package `agents`) is Cloudflare's framework for building and hosting stateful AI agents on Workers and Durable Objects.
Each agent session has a durable identity, local SQL storage, real-time connections, scheduled work, and recoverable execution, and Cloudflare says it scales "to tens of millions of instances".
The docs describe an agent as four composable parts: communication channels (chat, voice, email, Slack, webhooks), an agent harness (the model and tool loop: Project Think, Pi, or your own), the Agents SDK runtime (the `Agent` class, state, sessions, routing, WebSockets, scheduling, fibers, observability), and tools (Browser, Sandbox, AI Search, MCP, Payments, with Code Mode to orchestrate them).
The starter needs no API keys because it defaults to Workers AI: `npx create-cloudflare@latest --template cloudflare/agents-starter`, then `npm install` and `npm run dev`.
The starter includes streaming AI chat, server-side and client-side tools, human-in-the-loop approval, and task scheduling.
Source: https://developers.cloudflare.com/agents/

An `Agent` is a Durable Object: `Agent` extends `Server` from the `partyserver` package, which extends `DurableObject` (layers: DurableObject > Server > Agent).
An instance is globally unique per name, so the same name always reaches the same instance, and per-user, per-room or per-ticket state lives in the instance with no central session store.
Source: https://developers.cloudflare.com/agents/runtime/lifecycle/agent-class/ and https://developers.cloudflare.com/agents/runtime/agents-api/

### Key concepts

#### Lifecycle and core properties

| Hook | When it runs |
| --- | --- |
| `onStart(props?)` | Instance starts or wakes from hibernation; receives optional props from `getAgentByName` or `routeAgentRequest` |
| `onRequest(request)` | Each HTTP request |
| `onConnect(connection, ctx)` | WebSocket connection established |
| `onMessage(connection, message)` | Each WebSocket message |
| `onError(connection, error)` / `onError(error)` | Connection-level or server-level error |
| `onClose(connection, code, reason, wasClean)` | WebSocket closes |
| `onEmail(email)` | Email routed to the instance |
| `onStateChanged(state, source)` | State changes from server or client |

Core properties are `this.env`, `this.ctx`, `this.state`, `this.sql`, `this.name` and `this.mcp` (an `MCPClientManager`).
Source: https://developers.cloudflare.com/agents/runtime/agents-api/ and https://developers.cloudflare.com/agents/runtime/communication/websockets/

#### State and SQL

State is JSON-serializable, persisted to SQLite (table `cf_agents_state`), broadcast to all connected WebSocket clients, bidirectional (clients can call `setState` too), and read-your-own-writes consistent.
`initialState` is applied lazily on first access only; without it `this.state` is `undefined`.
`setState()` saves to SQLite, broadcasts (except to connections where `shouldSendProtocolMessages` returned `false`), then triggers `onStateChanged()` on a best-effort basis.
`this.sql` is a tagged template over the Durable Object's synchronous SQLite API, for data that does not need to sync to clients.
State is persistent data; props are one-time initialization arguments that do not persist.
Source: https://developers.cloudflare.com/agents/runtime/lifecycle/state/ and https://developers.cloudflare.com/agents/runtime/lifecycle/agent-class/

```ts
this.sql`CREATE TABLE IF NOT EXISTS users (id TEXT PRIMARY KEY, name TEXT)`;
this.sql`INSERT INTO users (id, name) VALUES (${id}, ${name})`;
const users = this.sql<User>`SELECT * FROM users WHERE id = ${id}`;
```

Source: https://developers.cloudflare.com/agents/runtime/agents-api/

Readonly connections (`shouldConnectionBeReadonly`, `setConnectionReadonly`, `isConnectionReadonly`) receive state but cannot call `setState()`, directly or through a `@callable()` method; side effects inside callables still run, and the flag is per connection, not per user.
Protocol messages (`cf_agent_identity`, `cf_agent_state`, `cf_agent_mcp_servers`) can be suppressed per connection with `shouldSendProtocolMessages()` for binary-only clients such as MQTT or IoT devices; this is set once on connect.
Source: https://developers.cloudflare.com/agents/runtime/communication/readonly-connections/ and https://developers.cloudflare.com/agents/runtime/communication/protocol-messages/

#### Callable methods (RPC over WebSocket)

`@callable()` exposes a method to browsers, apps and external services over WebSocket RPC; Worker-to-Agent and Agent-to-Agent calls should use plain Durable Object RPC (for example via `getAgentByName()`) with no decorator.
Arguments and return values must be JSON-serializable, and `@callable({ streaming: true })` methods receive a `StreamingResponse` with `send(chunk)`, `end(finalChunk?)` and `error(message)`.
Clients call `agent.stub.method()` (typed, recommended) or `agent.call(method, args?, options?)`.
The SDK uses TC39 standard decorators, so `"experimentalDecorators": true` must not be set, the target must be `ES2021` (shipped as `agents/tsconfig`), and Vite 8 projects need the `agents/vite` plugin because Oxc does not yet transform TC39 decorators.
Source: https://developers.cloudflare.com/agents/runtime/lifecycle/callable-methods/ and https://developers.cloudflare.com/agents/runtime/operations/configuration/

#### Scheduling, queue, retries

| Mode | Syntax |
| --- | --- |
| Delayed (seconds) | `this.schedule(60, "cb", payload)` |
| At a date | `this.schedule(new Date(...), "cb", payload)` |
| Cron (minute precision) | `this.schedule("0 8 * * *", "cb", payload)` |
| Interval (second precision, overlap prevention) | `this.scheduleEvery(30, "cb", payload)` |

Schedules live in the `cf_agents_schedules` table and multiplex many schedules onto the Durable Object's single alarm.
Cron schedules are idempotent by default (same cron, callback and payload return the existing schedule), so they are safe to declare in `onStart()`.
Management methods are `getScheduleById()`, `listSchedules()` and `cancelSchedule()`; `getSchedule()` and `getSchedules()` are deprecated.
Scheduling limits: tasks are bounded by SQLite storage ("tens of thousands per agent" in practice), each task including payload can be up to 2 MB, and the minimum delay is 0 seconds.
`getSchedulePrompt()` and `scheduleSchema` help a model produce schedules.
Source: https://developers.cloudflare.com/agents/runtime/execution/schedule-tasks/

`this.queue(callback, payload)` is a built-in FIFO queue in `cf_agents_queues`, processed sequentially with no priority and no parallelism.
Retries default to 3 attempts, 100 ms base delay, 3 s max delay with "Full Jitter" exponential backoff, for `this.retry()`, `queue()`, `schedule()` and `scheduleEvery()`, overridable per call or via `static options.retry`.
MCP connection retries default to 3 attempts, 500 ms base, 5 s max.
There is no dead-letter queue (a task that exhausts retries is removed), retry delays keep the agent awake, queue retries are head-of-line blocking, and `shouldRetry` only works on `this.retry()`.
Source: https://developers.cloudflare.com/agents/runtime/execution/queue-tasks/ and https://developers.cloudflare.com/agents/runtime/execution/retries/

#### Durable execution: keepAlive and fibers

Durable Objects get evicted after about 70 to 140 seconds of inactivity, on code updates or runtime restarts (non-deterministic, 1 to 2 times per day), and when an alarm handler exceeds 15 minutes.
`keepAlive()` / `keepAliveWhile(fn)` hold a reference-counted heartbeat alarm every 30 seconds (default) to prevent idle eviction, but do nothing for recovery; `AIChatAgent` calls it automatically while streaming.
`runFiber(name, fn)` runs work with checkpoints (`stash(data)`, written synchronously to SQLite), and after eviction `onFiberRecovered(ctx)` receives `ctx.name`, `ctx.snapshot`, `ctx.createdAt` and `ctx.recoveryReason` (currently always `"interrupted"`); the original closure cannot be replayed.
`startFiber(name, fn, { idempotencyKey, metadata, waitForCompletion })` durably accepts managed jobs that can be inspected (`inspectFiber`, `listFibers`), cancelled (`cancelFiber`), resolved (`resolveFiber`) and cleaned up (`deleteFibers`).
Source: https://developers.cloudflare.com/agents/runtime/execution/durable-execution/

#### Sub-agents and agents as tools

`subAgent(Cls, name)` spawns a child agent with isolated SQLite storage and typed RPC; children are Durable Object facets discovered through `ctx.exports`, so they need no separate binding, but they must be exported under their own class name and cannot be named `Sub`.
Related methods are `abortSubAgent()`, `deleteSubAgent()`, `hasSubAgent()`, `listSubAgents()` and the `onBeforeSubAgent` gate; clients reach children with `useAgent({ sub })` or `buildAgentUrl()`.
Inside a sub-agent, schedules, fibers, state and SQL work against the child's own storage, and `keepAlive()` delegates to the top-level parent.
Source: https://developers.cloudflare.com/agents/runtime/execution/sub-agents/

`agentTool()` (from `agents/agent-tools`) turns a Think or `AIChatAgent` subclass into an AI SDK tool, and `runAgentTool()` runs it imperatively, optionally `detached` for background work with a `maxBudgetMs` ceiling (default 24 hours) and a no-progress budget (default 1 hour).
Re-attach after interruption gives up after `agentToolReattachNoProgressTimeoutMs` (default 120,000 ms) without progress.
React UIs can render child timelines with `useAgentToolEvents()`.
Source: https://developers.cloudflare.com/agents/runtime/execution/agent-tools/

#### Workflows from agents

Use an Agent alone for chat and quick calls, and Agent plus Workflow for tasks over 30 seconds, multi-step pipelines and human approval.
`AgentWorkflow` gives the workflow a typed `this.agent` stub, non-durable `reportProgress()`, `broadcastToClients()` and `waitForApproval()`, and durable step methods `step.reportComplete()`, `step.reportError()`, `step.sendEvent()`, `step.updateAgentState()`, `step.mergeAgentState()` and `step.resetAgentState()`.
The Agent side has `runWorkflow()`, `sendWorkflowEvent()`, `getWorkflowStatus()`, `approveWorkflow()`, `rejectWorkflow()`, `pauseWorkflow()`, `resumeWorkflow()`, `restartWorkflow()`, `terminateWorkflow()`, `migrateWorkflowBinding()` and callbacks `onWorkflowProgress`, `onWorkflowComplete`, `onWorkflowError`, `onWorkflowEvent`.
Workflows cannot open WebSockets directly and talk to clients through the Agent.
Source: https://developers.cloudflare.com/agents/runtime/execution/run-workflows/

Contradiction: the Run Workflows page lists workflow limits of 10,000 steps (configurable to 25,000), 10 MB state per workflow, 1 year event wait and "30 minutes per step", while the Workflows limits page lists 100 MB (Free) or 1 GB (Paid) persisted state and unlimited wall time per step bounded by CPU time, and the Long-running agents page says "30 minutes per step, unlimited steps".
Sources: https://developers.cloudflare.com/agents/runtime/execution/run-workflows/, https://developers.cloudflare.com/workflows/reference/limits/ and https://developers.cloudflare.com/agents/concepts/agentic-patterns/long-running-agents/

#### Long-running agents

The docs pitch Durable Objects over VMs or containers for long-lived agents: zero idle cost when hibernated, built-in SQLite, platform restarts with surviving state, and built-in name-based routing ("10,000 agents, each active 1% of the time" means about 100 active at any moment).
Agents wake on HTTP, WebSocket, RPC, scheduled alarms or email.
Recommended strategies by duration: seconds use normal handling, minutes use `keepAlive()` or `startFiber()`, minutes to hours use Workflows, hours to days use start-job, hibernate, wake-on-completion.
Interrupted LLM streams are recovered per provider: Workers AI continues via assistant prefill (`continueLastTurn()`, low token cost), the OpenAI Responses API retrieves the completed response by ID (zero cost), and Anthropic uses a synthetic continuation message (medium cost).
Source: https://developers.cloudflare.com/agents/concepts/agentic-patterns/long-running-agents/

#### Memory: Sessions and context blocks

The experimental Session API (`agents/experimental/memory/session`) stores tree-structured messages (branching, non-destructive regeneration), context blocks, compaction and FTS5 full-text search, on Durable Object SQLite by default or Postgres through Hyperdrive (`PostgresSessionProvider`, `PostgresContextProvider`, `PostgresSearchProvider`).
Context block providers are `ContextProvider` (read-only), `WritableContextProvider` (model writes via `set_context`), `SkillProvider` (on-demand documents via `load_context` / `unload_context`) and `SearchProvider` (FTS5 via `search_context`); `SessionManager` adds cross-session `session_search`.
Compaction protects the first 3 messages and a 20K-token tail by default, summarizes the middle with an LLM, and stores the summary as an overlay in `assistant_compactions` without deleting originals.
Token estimation is heuristic (`max(chars/4, words*1.3)`), because tiktoken would add 80 to 120 MB of heap against the Workers 128 MB limit.
Storage tables include `assistant_messages`, `assistant_compactions`, `assistant_fts`, `assistant_sessions`, `cf_agents_context_blocks` and `cf_agents_search_entries`.
Source: https://developers.cloudflare.com/agents/runtime/lifecycle/sessions/ and https://developers.cloudflare.com/agents/concepts/conversation-state-and-memory/

#### Agent Skills

`agents/skills` gives an agent a catalog of on-demand instructions, resources and scripts, exposed as tools `activate_skill`, `read_skill_resource` and optional `run_skill_script`.
Script execution is opt-in, needs a Worker Loader binding, runs JavaScript, TypeScript (compiled with `@cloudflare/worker-bundler`), Python (as Python Dynamic Workers) and Bash (through `just-bash`), has read-only workspace access by default, and a 30-second default timeout.
Source: https://developers.cloudflare.com/agents/runtime/execution/agent-skills/

#### Harnesses: AIChatAgent, Project Think, Pi

`AIChatAgent` (`@cloudflare/ai-chat`) is the build-your-own chat base class: you implement `onChatMessage()`, and it gives message persistence, resumable streaming and `useAgentChat`.
It requires SQLite, compacts any message approaching the 2 MB SQLite row limit at about 1.8 MB, waits for MCP connections up to 10 seconds by default (`waitForMcpConnections`), and supports `messageConcurrency` strategies `queue` (default), `latest`, `merge`, `drop` and `debounce` (default 750 ms).
Its `chatRecovery` defaults are `maxAttempts` 10, `stableTimeoutMs` 10,000, `noProgressTimeoutMs` 300,000 and `maxRecoveryWork` 1,000.
Source: https://developers.cloudflare.com/agents/communication-channels/chat/chat-agents/

Project Think (`@cloudflare/think`) is an opinionated harness where a 3-line subclass (`getModel()` only) gets the WebSocket chat protocol, persistence, the agentic loop, stream resumption, client tools and workspace file tools.
Compared with `AIChatAgent`, Think uses Sessions storage (tree messages, context blocks, FTS5), non-destructive branching and compaction, sub-agent `chat()` RPC with `StreamCallback`, and programmatic turns (`saveMessages()`, `submitMessages()`, `continueLastTurn()`, `runTurn({ mode: "wait" | "submit" | "stream" })`).
Built-in workspace tools are `read`, `write`, `edit`, `list`, `find`, `grep`, `delete` and `bash` (a `just-bash` virtual filesystem with network disabled, snapshotting up to 1,000 files and skipping files over 1 MB), with optional R2 spillover for large files.
Tool merge order is workspace tools, `getTools()`, extension tools, session tools, skill tools, MCP tools (`includeMcpTools` default true), then client tools.
Defaults: `maxSteps` 10, `sendReasoning` true, `messageConcurrency` `"queue"`, `waitForMcpConnections` false, `chatStreamStallTimeoutMs` 0 (off).
Lifecycle hooks are `configureSession`, `beforeTurn`, `beforeStep`, `beforeToolCall`, `afterToolCall`, `onStepFinish`, `onChunk`, `onChatResponse`, `onChatError` and `classifyChatError`.
Experimental Actions (`action()`) add an idempotency ledger, approval-gated or durable-pause approvals with `approvalRisk`, declarative `permissions` with `authorizeTurn()`, and a 30,000 ms default timeout.
Channels (`web`, `messenger`, `voice`, `custom`) apply per-channel instructions, tool filters and step caps; messengers include Telegram through `@cloudflare/think/messengers/telegram` and Chat SDK adapters, with one Think sub-agent per thread by default.
`getScheduledTasks()` declares recurring prompt or handler turns with a DSL such as `every weekday at HH:mm`, and `ThinkWorkflow` with `step.prompt()` runs a durable structured-output turn inside a Workflow.
Package exports include `@cloudflare/think/workflows`, `/tools/workspace`, `/tools/execute` (Code Mode), `/tools/browser` and `/tools/extensions`; LLM-driven extensions need a `worker_loaders` binding.
Sources: https://developers.cloudflare.com/agents/harnesses/think/, https://developers.cloudflare.com/agents/harnesses/think/tools/, https://developers.cloudflare.com/agents/harnesses/think/configuration/, https://developers.cloudflare.com/agents/harnesses/think/actions/, https://developers.cloudflare.com/agents/harnesses/think/channels/, https://developers.cloudflare.com/agents/harnesses/think/scheduled-tasks/ and https://developers.cloudflare.com/agents/harnesses/think/workflows/

Contradiction: the Think overview says Think supports AI SDK v6 and v7 (`ai@^6` with `@ai-sdk/react@^3`, or `ai@^7` with `@ai-sdk/react@^4`), while the Think configuration page's dependency table lists `ai` as "AI SDK v6", and the `agents/models/ai-sdk` provider requires `ai@^7`.
Sources: https://developers.cloudflare.com/agents/harnesses/think/, https://developers.cloudflare.com/agents/harnesses/think/configuration/ and https://developers.cloudflare.com/agents/models/ai-sdk/

Think's chat recovery defaults match `AIChatAgent` (`maxAttempts` 10, `noProgressTimeoutMs` 5 minutes, `maxRecoveryWork` 1,000, `maxOomRetries` 3), and an exhausted recovery reports `no_progress_timeout`, `max_attempts_exceeded`, `work_budget_exceeded`, `recovery_aborted` or `out_of_memory`.
Optional `contextOverflow.reactive` and `contextOverflow.proactive` re-run or pre-empt a turn after compaction when the context window overflows.
Source: https://developers.cloudflare.com/agents/harnesses/think/recovery/

Pi (beta) runs Pi Durable (`@earendil-works/pi-durable` and `@earendil-works/pi-ai`, version 1.0 or later) inside an Agent or plain Durable Object through `PiHarness`, storing transcripts in `pi_`-prefixed SQLite tables and using a 30-second heartbeat Lifecycle job to restart work after eviction.
Pi limitations: no approval step for tool calls, no event-stream resume cursor, no conversation deletion, and a single model request streaming longer than 15 minutes (the alarm invocation limit) can be cut off.
Source: https://developers.cloudflare.com/agents/harnesses/pi/

#### Calling models

Agents can call Workers AI through the `AI` binding with no API keys, or OpenAI, Anthropic, Gemini and others through the AI SDK or OpenAI-compatible endpoints, optionally through AI Gateway.
Source: https://developers.cloudflare.com/agents/runtime/operations/using-ai-models/

The beta `createAI` providers route `@cf/` ids through `env.AI.run()` (with a compatibility layer to OpenAI chat-completions shape) and third-party AI SDK model objects through AI Gateway with `env.AI.gateway(id).run()`, so no vendor API key sits in the Worker; credentials come from AI Gateway Unified Billing or a key stored on the gateway, and the `default` gateway is created on first use.

```ts
import { createAnthropic } from "@ai-sdk/anthropic";
```

### MCP

#### Building MCP servers

Remote MCP servers use Streamable HTTP; stdio is for local servers; the old HTTP+SSE transport is deprecated.
As of 2026-10-05 the recommended server path is the stateless `createMcpHandler(factory, options)` from `agents/mcp/server` over MCP TypeScript SDK v2 (`@modelcontextprotocol/server`); `createLegacyMcpHandler` (`agents/mcp`, SDK v1 with `WorkerTransport`) is a temporary bridge, and `McpAgent` is deprecated and feature-frozen.
Sources: https://developers.cloudflare.com/agents/model-context-protocol/protocol/transport/ and https://developers.cloudflare.com/agents/model-context-protocol/apis/handler-api/

```ts
import { McpServer } from "@modelcontextprotocol/server";
import { createMcpHandler } from "agents/mcp/server";
import { z } from "zod";

function createServer() {
	const server = new McpServer({ name: "hello-server", version: "1.0.0" });
	server.registerTool(
		"hello",
		{ description: "Return a greeting", inputSchema: { name: z.string().optional() } },
		async ({ name }) => ({ content: [{ type: "text", text: `Hello, ${name ?? "World"}!` }] }),
	);
	return server;
}

export default {
	fetch(request, env, ctx) {
		return createMcpHandler(createServer)(request, env, ctx);
	},
} satisfies ExportedHandler;
```

Pass the factory, not a constructed server, and do not default-export the callable directly because Wrangler treats a function default export as a `WorkerEntrypoint` class.
`CreateMcpHandlerOptions` defaults: `route` `"/mcp"`, wildcard CORS, Origin allowlist of localhost, the `workers.dev` hostname and any concrete CORS origin, `legacy` `"stateless"` (or `"reject"`), `responseMode` `"auto"`, `maxSubscriptions` 1,024 and `keepAliveMs` 15,000.
On the stateless legacy-compatibility lane each POST gets a new server, GET and DELETE return 405, no session ID persists, and pushed elicitation, sampling and roots fail.
List changes are published with `notify.toolsChanged()`, `notify.promptsChanged()`, `notify.resourcesChanged()` and `notify.resourceUpdated(uri)`.
Source: https://developers.cloudflare.com/agents/model-context-protocol/apis/handler-api/

The MCP SDK v2 protocol (MCP 2026-07-28 revision) drops the `initialize` handshake and protocol sessions, puts version and capabilities on each request, replaces server-pushed requests with `input_required` multi-round-trip requests (MRTR), and uses `subscriptions/listen` instead of a standalone GET stream; proxies must preserve `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name` and `Mcp-Param-*` headers.
The draft deprecates Roots, Sampling, Logging, HTTP+SSE and Dynamic Client Registration.
Agents SDK v0.20.0 also deprecated `MCPClientManager.callTool(params, resultSchema, options)` and `withX402Client(...).callTool(confirm, params, resultSchema, options)` in favor of signatures without `resultSchema`.
Source: https://developers.cloudflare.com/agents/model-context-protocol/guides/migrate-to-mcp-sdk-v2/

Inconsistency: the Build a Remote MCP server guide's quick-deploy templates (`remote-mcp-authless`, `remote-mcp-github-oauth`, using `OAuthProvider` with `MyMCP.serve("/mcp")`) still use the deprecated `McpAgent` path, which the page itself warns against for new servers, and the Quick start's "Expose tools via MCP" link points to the deprecated `McpAgent` page.
Sources: https://developers.cloudflare.com/agents/model-context-protocol/guides/remote-mcp-server/ and https://developers.cloudflare.com/agents/getting-started/quick-start/

`McpAgent` (legacy) adds state, SQL, `props` from OAuth, `elicitInput()`, `McpAgent.serve(path, options)`, hibernation, EU jurisdiction, and stream resumability with an `EventStore` (25-second keepalive comment frames without one).
RPC transport lets an Agent call a same-Worker `McpAgent` through a Durable Object binding with no network hop and no auth, with a 60-second default tool response timeout.
Sources: https://developers.cloudflare.com/agents/model-context-protocol/apis/agent-api/ and https://developers.cloudflare.com/agents/model-context-protocol/protocol/transport/

#### Authorization

MCP uses a subset of OAuth 2.1, and the docs list four options: Cloudflare Access as OAuth provider, a third-party provider (GitHub, Google, Slack, Stytch, Auth0, WorkOS and others) wired through `workers-oauth-provider`'s `OAuthProvider`, your own OAuth provider, or the Worker handling auth itself.
Tools can check permissions inside handlers (the model sees a denial) or be registered conditionally (the model never sees them).
Securing guidance covers consent dialogs to prevent confused-deputy attacks, CSRF tokens, input sanitization, CSP, state binding, `__Host-` cookies and HMAC-signed cookies.
MCP server portals in Cloudflare One centralize several MCP servers behind one endpoint with identity, posture conditions and per-tool scope.
Sources: https://developers.cloudflare.com/agents/model-context-protocol/protocol/authorization/, https://developers.cloudflare.com/agents/model-context-protocol/guides/securing-mcp-server/ and https://developers.cloudflare.com/agents/model-context-protocol/protocol/governance/

#### MCP client (agent as MCP host)

```ts
await this.addMcpServer("GitHub", "https://mcp.github.com/mcp", {
	callbackHost: "https://my-worker.example.workers.dev",
});
await this.addMcpServer("internal-tools", this.env.MyMCP); // RPC to a Durable Object
const tools = this.mcp.getAITools(); // pass to the AI SDK
```

`addMcpServer(name, url, options)` returns `ready` or `authenticating` with an `authUrl`; options include `id` (stable IDs instead of `nanoid(8)`), `callbackPath` (required when `sendIdentityOnConnect` is false), `client` (transport `auto`, `streamable-http` or `sse`, plus headers), and `retry`.
Connection states are `authenticating`, `connecting`, `connected`, `discovering`, `ready` and `failed`, and connections persist in the agent's SQL storage.
The client blocks private and internal URLs (RFC 1918, link-local, unique-local, IPv4-mapped private, cloud metadata endpoints).
The default OAuth provider performs Dynamic Client Registration; `createMcpOAuthProvider()` overrides it, and `configureOAuthCallback()` and `configureElicitationHandlers()` customize callbacks and form or URL elicitation.
Sources: https://developers.cloudflare.com/agents/model-context-protocol/apis/client-api/, https://developers.cloudflare.com/agents/tools/mcp/ and https://developers.cloudflare.com/agents/model-context-protocol/guides/oauth-mcp-client/

### Tools

#### Code Mode

Code Mode (experimental) gives the model one code tool and typed interfaces instead of many tool definitions, so it can compose dependent calls, loop, branch, filter and shape results in one plan.
`DynamicWorkerExecutor` runs each execution pass in an isolated Worker created by the Worker Loader binding, with `globalOutbound: null` (network blocked) and a 60,000 ms timeout by default; the sandbox has no Node APIs, credentials, `process` or `require`, and reaches outside only through connectors.
The durable runtime (`createCodemodeRuntime`, a Durable Object facet exported as `CodemodeRuntime`) records every connector call, pauses on `requiresApproval` methods, resumes by deterministic replay (`approve()`), supports `reject()`, `rollback()` through `revert` functions, `expirePaused()` (24 hours default), saved snippets, and keeps 50 terminal executions by default.
Each durable value is limited to 1,000,000 serialized characters, and results are truncated to about 6,000 tokens by default.
Integrations: AI SDK (`createCodeTool()` from `@cloudflare/codemode/ai`, or `ToolSetConnector` for durable approvals), TanStack AI, browser iframe executor (`IframeSandboxExecutor`, 30,000 ms timeout), MCP connections (`McpConnector`) and OpenAPI services.

## Agentic payments (x402 and MPP)

This section covers `raw/docs/agents/tools/payments/` in full, plus the other Cloudflare pages that put x402 into products (AI Gateway Machine Payments, Monetization Gateway, the AI Crawl Control x402 template) and the related blog and press material.
The payments pages sit under Agents > Tools in the sidebar.

### What it is

AI agents need to discover, pay for and consume services programmatically, and the traditional flow (account creation, payment method, API key) blocks them.
Agentic payments let an agent buy a resource directly through the HTTP `402 Payment Required` status code, with no pre-created service account or pre-shared API key.
The Agents SDK supports two protocols built on HTTP 402: x402 and the Machine Payments Protocol (MPP).
Both follow the same core flow:

1. A client requests a resource or calls a tool.
2. The server returns a payment Challenge describing what to pay, how much and where.
3. The client fulfils the payment and retries with a payment credential.
4. The server verifies the payment (optionally through a facilitator) and returns the resource with a receipt.

Source: https://developers.cloudflare.com/agents/tools/payments/ (last updated Aug 5, 2026).

  Source: https://developers.cloudflare.com/agents/tools/payments/

### x402: protocol summary

x402 is a payment standard created by Coinbase.
It uses on-chain stablecoin payments ("USDC on Base, Ethereum, Solana, and other networks") and defines three HTTP headers: `PAYMENT-REQUIRED` (challenge), `PAYMENT-SIGNATURE` (credential) and `PAYMENT-RESPONSE` (receipt).
Servers can offload verification and settlement to a facilitator so they need no blockchain connectivity.
x402 is governed by Coinbase and Cloudflare, two of the founding members of the x402 Foundation.
Source: https://developers.cloudflare.com/agents/tools/payments/

Request flow as the x402 page states it:

1. Client sends `GET /resource`.
2. Server returns `402 Payment Required` with a `PAYMENT-REQUIRED` header holding Base64-encoded payment details: price, accepted token, network and merchant address.
3. Client builds a signed payment payload and retries with a `PAYMENT-SIGNATURE` header.
4. Server verifies the payload, directly or through a facilitator, and settles on-chain.
5. Server returns the resource with a `PAYMENT-RESPONSE` header containing settlement confirmation.

Source: https://developers.cloudflare.com/agents/tools/payments/x402/ (last updated Jun 3, 2026).

Roles:

- Client: a human-operated app, an AI agent or a service; it needs only a crypto wallet, with no accounts, credentials or session tokens.
- Server: defines requirements in the 402, verifies payloads, settles, serves the resource; SDKs and a facilitator handle most of this.
- Facilitator: optional but recommended; exposes `POST /verify` (confirm the payload is valid before fulfilling) and `POST /settle` (submit the verified transaction on-chain).
  It does not hold funds; it verifies and broadcasts the client's pre-signed transaction.
  `https://x402.org/facilitator` is the public facilitator operated by Coinbase and is used in all Cloudflare examples; more facilitators are listed at https://www.x402.org/ecosystem?filter=facilitators.

Source: https://developers.cloudflare.com/agents/tools/payments/x402/

Schemes and networks (as of 2026-10-05):

| Scheme | Networks | Description |
| --- | --- | --- |
| `exact` | EVM, Solana, Aptos, Stellar, Hedera, Sui | Transfers a fixed token amount, typically ERC-20 USDC on EVM, to the merchant address. |
| `upto` | EVM | Authorizes a maximum amount; the actual charge is set at settlement time from resource consumption. |

"Supported networks include Base, Ethereum, Polygon, Optimism, Arbitrum, Avalanche, Solana, Aptos, Stellar, and Sui."
Use `base-sepolia` for testing, with free test USDC from the Circle Faucet (https://faucet.circle.com/).
Source: https://developers.cloudflare.com/agents/tools/payments/x402/

Note on the chain lists: the scheme table names Hedera for `exact`, but Hedera is missing from the "Supported networks" sentence on the same page, and the sentence ends with "include", so neither list claims to be exhaustive.
Every Cloudflare code sample on these pages uses only `base` or `base-sepolia`, and the client helpers shown (`@x402/evm`, `registerExactEvmScheme`, viem `privateKeyToAccount`) are EVM-only; no Solana client or server sample appears in the Cloudflare docs.

### x402: charge for HTTP content (seller side)

Option 1, the `x402-proxy` template: a Worker in front of any HTTP backend that returns 402 on protected routes, verifies payment and forwards to the origin.
Deploy button source: https://github.com/cloudflare/templates/tree/main/x402-proxy-template.
Prerequisites: a Cloudflare account, an HTTP backend and a wallet address to receive payments.
Configuration lives in `wrangler.jsonc` vars:

```json
{
	"vars": {
		"PAY_TO": "0xYourWalletAddress",
		"NETWORK": "base-sepolia",
		"PROTECTED_PATTERNS": [
			{ "pattern": "/api/premium/*", "price": "$0.10", "description": "Premium API access" }
		]
	}
}
```

`base-sepolia` is a test network; change it to `base` for production.
With Bot Management, a pattern can charge only bots: requests with a bot score at or below `bot_score_threshold` go to the paywall, and `except_detection_ids` allowlists specific crawlers by detection ID (example: `"bot_score_threshold": 30, "except_detection_ids": [117479730]`).
Deploy with `git clone https://github.com/cloudflare/templates`, `cd templates/x402-proxy-template`, `npm install`, `npx wrangler deploy`.
Source: https://developers.cloudflare.com/agents/tools/payments/x402/charge-for-http-content/ (last updated Jun 3, 2026).

Option 2, Hono middleware inside your own Worker:

```ts
import { Hono } from "hono";
import { paymentMiddleware } from "x402-hono";

const app = new Hono<{ Bindings: Env }>();
app.use(
	paymentMiddleware(
		"0xYourWalletAddress" as `0x${string}`,
		{ "/premium": { price: "$0.10", network: "base-sepolia", config: { description: "Premium content" } } },
		{ url: "https://x402.org/facilitator" },
	),
);
app.get("/premium", (c) => c.json({ message: "Thanks for paying!" }));
export default app;
```

Source: https://developers.cloudflare.com/agents/tools/payments/x402/charge-for-http-content/

### x402: charge for MCP tools (seller side)

`paidTool` is a drop-in replacement for `tool` that adds x402 requirements; free and paid tools can be mixed on one server.
Wrap the `McpServer` with `withX402`:

```ts
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { McpAgent } from "agents/mcp";
import { withX402, type X402Config } from "agents/x402";
import { z } from "zod";

const X402_CONFIG: X402Config = {
	network: "base",
	recipient: "0xYourWalletAddress",
	facilitator: { url: "https://x402.org/facilitator" },
};

export class PaidMCP extends McpAgent<Env> {
	server = withX402(new McpServer({ name: "PaidMCP", version: "1.0.0" }), X402_CONFIG);
	async init() {
		this.server.paidTool("square", "Squares a number", 0.01 /* USD */, { number: z.number() }, {},
			async ({ number }) => ({ content: [{ type: "text", text: String(number ** 2) }] }));
		this.server.tool("echo", "Echo a message", { message: z.string() },
			async ({ message }) => ({ content: [{ type: "text", text: message }] }));
	}
}
```

`X402Config` fields: `network` (`base` for production, `base-sepolia` for testing), `recipient` (wallet address) and `facilitator` (use `https://x402.org/facilitator`).
Signature: `paidTool(name, description, price /* USD, e.g. 0.01 */, inputSchema /* Zod */, annotations /* MCP */, handler)`.
An unpaid call returns 402 with payment requirements; the client pays via x402, retries with proof and gets the result.
Working example: https://github.com/cloudflare/agents/tree/main/examples/x402-mcp.
Source: https://developers.cloudflare.com/agents/tools/payments/x402/charge-for-mcp-tools/ (last updated Jun 3, 2026).

### x402: pay from the Agents SDK (buyer side)

The Agents SDK MCP client can pay x402-protected tools by wrapping a connection with `withX402Client`:

```ts
import { Agent } from "agents";
import { withX402Client } from "agents/x402";
import { privateKeyToAccount } from "viem/accounts";

export class MyAgent extends Agent {
	async onStart() {
		const { id } = await this.mcp.connect(`${this.env.WORKER_URL}/mcp`);
		const account = privateKeyToAccount(this.env.MY_PRIVATE_KEY);
		this.x402Client = withX402Client(this.mcp.mcpConnections[id].client, { network: "base-sepolia", account });
	}
	onPaymentRequired(paymentRequirements): Promise<boolean> {
		// human-in-the-loop confirmation
	}
	async onToolCall(toolName: string, toolArgs: unknown) {
		// first argument is the confirmation callback; pass null to pay automatically
		return await this.x402Client.callTool(this.onPaymentRequired, { name: toolName, arguments: toolArgs });
	}
}
```

Store the key in `.dev.vars` locally (`MY_PRIVATE_KEY="0x..."`) and with `npx wrangler secret put MY_PRIVATE_KEY` in production.
Source: https://developers.cloudflare.com/agents/tools/payments/x402/pay-from-agents-sdk/ (last updated Jun 3, 2026).

### x402: pay from coding tools

Both recipes need a wallet key in `X402_PRIVATE_KEY` and the packages `@x402/fetch`, `@x402/evm` and `viem`.
They build a paying fetch with `new x402Client()`, `registerExactEvmScheme(client, { signer: account })` and `wrapFetchWithPayment(fetch, client)`.

### MPP (Machine Payments Protocol)

MPP (https://mpp.dev) is an open protocol for machine-to-machine payments that standardizes HTTP 402 with a formal authentication scheme proposed to the IETF (https://paymentauth.org).
It adds the `WWW-Authenticate: Payment` and `Authorization: Payment` headers to 402 exchanges, and a paid response carries a `Payment-Receipt` header.
It is payment-method agnostic: stablecoins, cards through Stripe, and custom methods, and one service can offer several.
MCP tools use the same flow through JSON-RPC, with the receipt returned in `_meta`.
Payment intents: `charge` (one-time), `session` (measured usage) and `subscription` (recurring access).
MPP is backwards-compatible with x402: MPP clients can consume existing x402 services without changes to those services.
SDKs exist for TypeScript, Python, Rust, Go and Ruby; the Cloudflare guides use the TypeScript `mppx` SDK.
Sources: https://developers.cloudflare.com/agents/tools/payments/mpp/ and https://developers.cloudflare.com/agents/tools/payments/ (last updated Aug 5, 2026).

The Cloudflare MPP samples all use the `tempo` payment method from `mppx` (`tempo.charge({ testnet: true })` on the server, `tempo.charge({ account })` on the client) with currency `0x20c0000000000000000000000000000000000000` on testnet.
The mpp-proxy template's production currency is `0x20c000000000000000000000b9537d11c60e8b50` with `TEMPO_TESTNET: false`.
The docs never say what Tempo is or which token those addresses represent; they only call it "a stablecoin payment method on testnet" and point to https://mpp.dev/payment-methods/ for other methods.
Source: https://developers.cloudflare.com/agents/tools/payments/mpp/accept-payments/ and https://developers.cloudflare.com/agents/tools/payments/mpp-charge-for-http-content/

#### MPP: charge for HTTP content with mpp-proxy

The `mpp-proxy` template (https://github.com/cloudflare/mpp-proxy) is a Worker in front of any HTTP backend; after payment it verifies, forwards to the origin, and issues a 1-hour session cookie.

```jsonc
{
	"vars": {
		"PAY_TO": "0xYourWalletAddress",
		"TEMPO_TESTNET": false,
		"PAYMENT_CURRENCY": "0x20c000000000000000000000b9537d11c60e8b50",
		"PROTECTED_PATTERNS": [
			{ "pattern": "/premium/*", "amount": "0.01", "description": "Access to premium content for 1 hour" }
		]
	}
}
```

For testnet set `TEMPO_TESTNET` to `true` and `PAYMENT_CURRENCY` to `0x20c0000000000000000000000000000000000000`.
The same `bot_score_threshold` and `except_detection_ids` options charge bots only (example allowlists `120623194` and `117479730`).
Deploy needs two secrets: `npx wrangler secret put JWT_SECRET` and `npx wrangler secret put MPP_SECRET_KEY`.
Source: https://developers.cloudflare.com/agents/tools/payments/mpp-charge-for-http-content/

#### MPP: accept payments on a Worker route or MCP tool

Worker route (`npm i hono mppx`, secret `MPP_SECRET_KEY`):

```ts
import { env } from "cloudflare:workers";
import { Hono } from "hono";
import { Mppx, tempo } from "mppx/hono";

const app = new Hono();
const mppx = Mppx.create({ methods: [tempo.charge({ testnet: true })], secretKey: env.MPP_SECRET_KEY });
app.get("/premium",
	mppx.charge({ amount: "0.01", currency: "0x20c0000000000000000000000000000000000000",
		description: "Premium API access", recipient: "<YOUR_WALLET_ADDRESS>" }),
	(c) => c.json({ access: "paid" }));
export default app;
```

An unpaid `curl -i` gets `402 Payment Required` with `WWW-Authenticate: Payment`; a paid retry reaches the handler and returns `Payment-Receipt`.

MCP tool (`npm i agents mppx @modelcontextprotocol/sdk zod`; Durable Object binding `MCP_OBJECT` for class `PaidMCP` with a `new_sqlite_classes` migration and `nodejs_compat`):

```ts
import { Mppx, tempo, Transport } from "mppx/server";
// inside McpAgent.init():
const mppx = Mppx.create({ methods: [tempo.charge({ testnet: true })], secretKey: this.env.MPP_SECRET_KEY, transport: Transport.mcpSdk() });
this.server.tool("premium_search", "Search premium content", { query: z.string() }, async ({ query }, extra) => {
	const payment = await mppx.charge({ amount: "0.01", currency: "0x20c0000000000000000000000000000000000000",
		description: "Premium search", recipient: "<YOUR_WALLET_ADDRESS>" })(extra);
	if (payment.status === 402) throw payment.challenge;
	return payment.withReceipt({ content: [{ type: "text", text: `Results for: ${query}` }] });
});
// export default PaidMCP.serve("/mcp");
```

Source: https://developers.cloudflare.com/agents/tools/payments/mpp/accept-payments/

#### MPP: pay from the Agents SDK

Install `agents mppx viem`, store `MPP_PRIVATE_KEY` as a secret, and build the method once with `tempo.charge({ account: privateKeyToAccount(key) })` from `mppx/client`.
For production agents the page advises a scoped access key with spending limits and recipient restrictions (https://mpp.dev/guides/managing-agent-spend).
HTTP: `Mppx.create({ acceptPaymentPolicy: { origins: ["https://api.example.com"] }, methods, polyfill: false })` then `this.payments.fetch(url)`; free endpoints pass through, paid ones retry and return `Payment-Receipt`.
MCP: connect with `this.addMcpServer(name, url)`, handle `connection.state === "authenticating"` by returning `connection.authUrl`, `await this.mcp.waitForConnections()`, then `McpClient.wrap(mcpConnection.client, { methods })` from `mppx/mcp/client` and `client.callTool(...)`; the receipt is in `result.receipt`.
By default both clients pay compatible Challenges automatically; use `onChallenge` (HTTP) or `onPaymentRequired` (MCP) to require approval.
Challenge amounts are integer base units, not decimal display values.
The `mppx` HTTP client also recognizes x402 Challenges if an x402-compatible EVM method is configured next to the MPP method (https://mpp.dev/guides/use-mpp-with-x402).
Source: https://developers.cloudflare.com/agents/tools/payments/mpp/pay-from-agents-sdk/

## Agent Memory

### What it is

Agent Memory is a managed service that gives agents persistent, scoped memory across conversations, without building your own extraction, storage, search and summarization pipeline.
You either ingest conversations so it extracts memories automatically, or explicitly `remember()` something the application already knows.
Typical contents: user preferences, company operating rules, support history, project state, or the state of a specific object.
It offers isolated profiles (users, agents, tenants, teams, entities), namespaces (applications, environments, memory layers), automatic extraction of facts, events, instructions and tasks, APIs to add, list, recall and delete, and profile summaries.
Source: https://developers.cloudflare.com/agent-memory/

### Status (as of 2026-10-05)

Agent Memory is in private beta, and the get-started guide says "You also need access to Agent Memory."
Cloudflare is not billing for it during the private beta and promises at least 30 days notice before charging.
Sources: https://developers.cloudflare.com/agent-memory/, https://developers.cloudflare.com/agent-memory/platform/pricing/, https://developers.cloudflare.com/agent-memory/get-started/

### Key concepts

- Memory types: Facts (stable knowledge; newer facts on the same topic supersede older ones, which are kept), Events (completed, time-anchored actions; they accumulate), Instructions (reusable procedures; support supersession), Tasks (short-lived, session-scoped; deprioritized after the session ends).
- Ingestion pipeline: extraction (AI finds discrete items), classification (type, topic key, keywords, search queries), deduplication (within the batch and against stored memories; same topic key supersedes), storage (durable storage with full-text indexes; non-task memories are also embedded as vectors).
  Raw messages are always stored verbatim alongside extracted memories.
- Recall pipeline: AI query analysis (keywords, topic keys, vectors), parallel retrieval across keyword indexes, topic keys, vector indexes and raw messages, combined scoring and ranking, then AI synthesis of a natural-language answer; with no match it returns an empty answer rather than hallucinating.
- Idempotency: messages are content-addressed per session, sessions are derived from content when no `sessionId` is given, so re-ingesting creates no duplicates.
- Isolation: `namespace > profile > memory`; a `recall()` on one profile never returns another profile's memories; sessions are scoped to a profile.

Sources: https://developers.cloudflare.com/agent-memory/concepts/how-agent-memory-works/, https://developers.cloudflare.com/agent-memory/concepts/namespaces-profiles/

### API and binding surface

Create a namespace with `npx wrangler agent-memory namespace create my-agent`, then bind it:

```jsonc
{
  "agent_memory": [
    { "binding": "MEMORY", "namespace": "my-agent" }
  ]
}
```

`npx wrangler types` generates `MEMORY: AgentMemoryNamespace`.
Namespace methods: `getProfile(name)` (creates the profile if missing; the first call may be slower) and `deleteProfile(name)`.
Profile methods:

- `ingest(messages, { sessionId? })`: messages are `{ role: "system" | "user" | "assistant", content, timestamp? }`; idempotent.
- `remember({ content, sessionId? })`: returns the stored `AgentMemoryMemory` (`id`, `type`, `summary`, `content`, `sessionId`, `createdAt`, `updatedAt`).
- `recall(query, { thinkingLevel: "low" | "medium" | "high", responseLength: "short" | "medium" | "long", referenceDate })`: returns `{ count, answer, candidates[{ id, summary, sessionId, score }] }`; defaults are `low` and `medium`.
- `list({ limit, cursor, sessionId, type })`: entries omit `content`.
- `get(id)`, `delete(id)` (also removes linked source messages), `deleteSession(sessionId)`, `getSummary({ sessionId })` (Markdown summary of the profile).

Source: https://developers.cloudflare.com/agent-memory/api/workers-api/

HTTP API base: `https://api.cloudflare.com/client/v4/accounts/<ACCOUNT_ID>/agent-memory/namespaces`, with `/{ns}/profiles/{profile}/ingest`, `/remember`, `/recall`, `/memories`, `/memories/{id}`, `/sessions/{id}` (DELETE) and `/summary` (POST).
Errors are standard Cloudflare v4 envelopes (400 invalid name, 401 auth, 404 namespace or profile not found, 409 namespace exists).
Source: https://developers.cloudflare.com/agent-memory/api/http-api/

The get-started guide pairs it with the Agents SDK Session API (`import { Session } from "agents/experimental/memory/session"`), which turns a searchable context provider into a model-callable `search_context` tool.
It advises against calling `ingest()` after every turn; batch it when the user goes idle, at compaction, or at another checkpoint.
Source: https://developers.cloudflare.com/agent-memory/get-started/ (last updated Aug 25, 2026)

## Sandboxes

### What it is

A sandbox is an isolated place to run untrusted or generated code: agent-written code, user-uploaded apps, data analysis, dev previews or build pipelines.
The code cannot read your application's memory or data; your Worker decides which APIs and data it receives and whether it can reach the Internet.
Cloudflare offers two sandbox environments, both driven from a Worker:

- Containers: a full Linux image you provide, run in a Firecracker microVM with its own kernel and network, started by a Durable Object with `this.ctx.container`.
  Use this when the code expects Linux (npm test, compilers, native binaries, long-running servers).
- Dynamic Workers: a new Worker created at runtime from JavaScript, Python or WebAssembly (compile TypeScript first), isolated by V8 plus a process-level sandbox; it reaches your app only through methods you pass.
  Use this when generated code only needs methods you define (Code Mode uses it).

Sources: https://developers.cloudflare.com/sandbox/, https://developers.cloudflare.com/sandbox/concepts/ (last updated Sep 30, 2026)

### Status (as of 2026-10-05)

- Sandboxes are "Available on Workers Paid plan"; Dynamic Workers are also Workers Paid only.
- A sandbox container uses the Durable Object scheduling policy, which is in public beta.
- Container snapshots are in public beta.
- The docs were rewritten for `@cloudflare/sandbox` 1.0 (example Dockerfile copies the shim from `cloudflare/sandbox:1.0.0`); Sandbox SDK 0.x (the 0.12 `Sandbox` class with `getSandbox()`) is documented separately for existing apps, with a migration guide.

Sources: https://developers.cloudflare.com/sandbox/, https://developers.cloudflare.com/sandbox/concepts/lifetime/, https://developers.cloudflare.com/sandbox/reference/, https://developers.cloudflare.com/dynamic-workers/pricing/

### Key concepts

- Lifetime: a Linux sandbox is a name, a Durable Object (reached with `getByName()`), and a Containers instance that runs only while something keeps it running.
- Activity (requests, alarms, streamed responses, accepted WebSockets) keeps the instance up; after the Durable Object goes idle the instance lives for `setInactivityTimeout()`, up to 6 hours, else it stops shortly after.
- Code running inside the instance does not count as activity, so long builds need an alarm that checks on them.
- The timeout does not survive a Durable Object restart (deploys restart every Durable Object), so set it again in the constructor.
- An instance stops when the timeout ends (processes get `SIGTERM`), on `destroy()` (immediate), or when the main process exits; `cloudflare/debian-trixie`'s default command exits at once, so examples use `sleep infinity`.
- Deploys keep running instances (same image and env); rollouts never replace a sandbox; new images apply only to new instances.
- Files and processes end with the instance; `snapshotContainer()` saves the writable root filesystem (not mounts, memory or processes); snapshots expire 30 days after creation or last restore (max 20 GB); restoring is your app's job.
- Mounted R2 buckets outlive every instance and must be remounted each time.
- Security: the sandbox is the smallest unit of trust; every process has root-equivalent capabilities; anything you put inside (env vars, tokens in `.git/config`, files) can be read and exfiltrated.
  Keep credentials in the Worker: Containers start with `enableInternet: false` by default and reach only hostnames you intercept with `interceptOutboundHttps()`, where a Worker entrypoint adds the token; Dynamic Workers loaded with `globalOutbound: null` cannot fetch at all.
  Derive sandbox names from authenticated identity, treat output as untrusted input, and serve previews on separate hostnames.
  Outbound handlers see only ports 80 and 443; with Internet on, other ports go out directly.

Sources: https://developers.cloudflare.com/sandbox/concepts/lifetime/, https://developers.cloudflare.com/sandbox/concepts/security/, https://developers.cloudflare.com/sandbox/network/, https://developers.cloudflare.com/containers/platform/limits/

### API surface

Wrangler (Containers, Durable Object scheduling policy):


```ts

export class MyContainer extends DurableObject<Env> {
	async exec(argv: string[]) {
```

## Vectorize

### What it is

Vectorize is a globally distributed vector database for building AI applications with Workers.
It stores embeddings from Workers AI models or from external providers such as OpenAI, and supports search, similarity, recommendation, classification and anomaly detection over your own data.
Vector results can point to objects in R2, documents in KV or rows in D1, so you go from a match to the concrete object without other infrastructure.
Source: https://developers.cloudflare.com/vectorize/

### Status (as of 2026-10-05)

Generally available since 2024-09-26 (changelog); available on the Workers Free plan since 2024-09-16.
Legacy V1 indexes were deprecated on 2024-08-14; V2 needs Wrangler 3.71.0 or later, and V1 operations use `wrangler vectorize --deprecated-v1`.
The docs say that "by December 2024, you will not be able to create legacy Vectorize indexes", and that there is no way to migrate existing V1 indexes to V2.
Sources: https://developers.cloudflare.com/vectorize/platform/changelog/, https://developers.cloudflare.com/vectorize/best-practices/create-indexes/

### Key concepts

- Index: the unit of storage, created with a kebab-case name, a fixed dimension count and a fixed distance metric; configuration cannot change after creation; names of deleted indexes can be reused (since 2024-12-20).
- Metrics: `cosine` (-1 to 1, 1 identical), `euclidean` (L2, 0 identical) and `dot-product` (negative dot product; lower is more similar).
- Scoring: approximate scoring is the default; `returnValues: true` switches to high-precision scoring, with more latency.
- Vectors: `id` (string, maps to your object), optional `namespace`, `values` (`number[]`, `Float32Array` or `Float64Array`, stored as Float32) and optional `metadata`.
- Insert keeps the first vector with a given id; upsert replaces it in full (no merge).
  Writes are asynchronous, return a mutation id, and take a few seconds to become queryable.
- Namespaces partition an index (for example per customer) and are applied before the vector search and before metadata filters.
- Metadata filtering needs a metadata index per property (max 10, types `string`, `number`, `boolean`), created before the vectors are inserted; strings index the first 64 bytes; only indexes created on or after 2023-12-06 support filtering.
- Filter operators: `$eq`, `$ne`, `$in`, `$nin`, `$lt`, `$lte`, `$gt`, `$gte`; keys use `.` for nesting; the filter JSON must be under 2,048 bytes; ranges on about 10M or more vectors may lose accuracy; string ranges give prefix search.
- High-cardinality metadata (for example millisecond timestamps) makes range filters slow, and the docs advise bucketing values.

Sources: https://developers.cloudflare.com/vectorize/best-practices/create-indexes/, https://developers.cloudflare.com/vectorize/best-practices/insert-vectors/, https://developers.cloudflare.com/vectorize/reference/metadata-filtering/, https://developers.cloudflare.com/vectorize/best-practices/query-vectors/

## AI Search

### What it is

AI Search (formerly AutoRAG) is a managed search service: create an instance, give it data (built-in storage uploads, an R2 bucket, or a website you own), and query it in natural language from a Workers binding, the REST API or an MCP server.
It handles Markdown conversion, chunking, embedding, keyword indexing, retrieval, optional reranking and optional answer generation.
Features include continuous automated indexing, metadata filtering, hybrid search (on by default), image search with multimodal embeddings, OCR for scanned PDFs and images, and a built-in MCP endpoint and UI snippets per instance.
Use cases named: docs and knowledge-base search, research agents over internal knowledge, and per-tenant or per-agent file search.
Sources: https://developers.cloudflare.com/ai-search/, https://developers.cloudflare.com/ai-search/platform/release-note/

### Status (as of 2026-10-05)

Generally available since 2026-10-01 and "Available on all plans"; usage-based billing begins on November 1, 2026.
All instances were migrated to managed infrastructure (built-in storage, built-in vector index and built-in crawling) by 2026-06-18.
The legacy `env.AI.autorag()` binding and the old AutoRAG REST endpoints still work, but new features ship only on the new bindings and endpoints.
The crawler user agent was renamed from `Cloudflare-AutoRAG` to `Cloudflare-AI-Search` on 2026-02-09 (the old name still works in `robots.txt`; Bot Detection ID `122933950`).
Sources: https://developers.cloudflare.com/ai-search/platform/release-note/, https://developers.cloudflare.com/ai-search/api/migration/workers-binding/

### Key concepts

- Indexing pipeline (asynchronous): ingest from the data source or the Items API, convert to Markdown with Workers AI `toMarkdown()`, chunk, embed (multimodal models embed image pixels; text models embed generated captions), BM25 keyword-index when enabled, then store.
- Query pipeline (synchronous): optional query rewriting (a Workers AI LLM), query embedding, vector search, BM25 keyword search in parallel when hybrid, fusion (`rrf` or `max`), optional cross-encoder reranking, chunk retrieval (the Search endpoint stops here), then optional generation (Chat Completions).
- Search modes: vector, keyword (BM25) and hybrid (the default for new instances); opt out with `index_method: { vector: true, keyword: false }`.
- Namespaces: every instance belongs to a namespace (a `default` one exists); instance names are unique per namespace; a namespace can expose one public endpoint that searches several instances.
- Data sources: built-in storage (R2 and Vectorize managed for you), an R2 bucket (needs a service API token), or a website you own (sitemap or `discover` parse type, Browser Run rendering optional, auth headers, CSS content selectors, meta-tag custom metadata, path include and exclude rules).
- Sync: every 6 hours by default; allowed `sync_interval` values in seconds are 900, 1800, 3600, 7200, 14400, 21600, 43200 and 86400; manual sync at most once per 30 seconds.
- Chunking: chunk size in tokens (range depends on the model), overlap 0% to 30%.
- Similarity cache: MinHash and LSH over prompt shingles; thresholds `super_strict_match`, `close_enough` (default), `flexible_friend`, `anything_goes`; `cache_ttl` 10 minutes to 6 days, default 48 hours.
- AI Search versus Vectorize: AI Search is built on Vectorize; use Vectorize to manage vectors yourself and AI Search for managed search or RAG.

Sources: https://developers.cloudflare.com/ai-search/concepts/how-ai-search-works/, https://developers.cloudflare.com/ai-search/concepts/search-modes/, https://developers.cloudflare.com/ai-search/concepts/namespaces/, https://developers.cloudflare.com/ai-search/configuration/indexing/syncing/, https://developers.cloudflare.com/ai-search/configuration/indexing/chunking/, https://developers.cloudflare.com/ai-search/configuration/retrieval/cache/

Supported file types: plain text and code (`.txt`, `.md`, `.mdx`, `.json`, `.yaml`, `.toml`, `.sql`, `.ts`, `.tsx`, `.js`, `.py`, `.go`, `.rs`, `.java`, `.swift`, `.dart`, `.tf`, `.sh` and more, up to 10 MiB) and rich formats converted to Markdown (PDF, images including `.gif` and `.bmp`, HTML, XML, Office `.docx` and `.xlsx`, ODF, CSV, `.numbers`; 4 MiB, or 10 MiB for PDFs with OCR).
Solidity (`.sol`) and Move files are not in the list.
Source: https://developers.cloudflare.com/ai-search/configuration/data-source/

## Web Search API

### What it is

Web Search API lets agents and applications search the Internet and ground responses in live results (titles, URLs, descriptions), instead of guessing URLs or relying on training cutoffs.
Every search runs through an AI Gateway, so it gets the gateway's logging, analytics, billing (Unified Billing) and access controls, plus bring-your-own-key.
Providers are Ceramic.ai (default), Exa and Linkup; responses are normalized to one format (URL, title, optional description, image, favicon, last-modified date), so switching provider is one parameter.
Every provider has committed to Cloudflare's verified-bot requirements (identify the crawler, respect `robots.txt`) and to source attribution on every result.
Sources: https://developers.cloudflare.com/web-search/, https://developers.cloudflare.com/web-search/about/

### Status (as of 2026-10-05)

Open beta; all four pages were last updated Oct 2, 2026.
Source: https://developers.cloudflare.com/web-search/

### API and binding surface

REST: `POST https://api.cloudflare.com/client/v4/accounts/{account_id}/ai/websearch/` with an API token holding Account > Workers AI > Read and Account > AI Gateway > Read.
Body: `query` (required, 1 to 1,024 chars), `provider` (`ceramic` default, `exa`, `linkup`), `limit` (1 to 10, default 10), `byokAlias` (pattern `^[A-Za-z0-9_-]{1,64}$`), and required `options.gateway.id` (every account has a gateway named `default`).
Worker binding: the existing Workers AI binding (`"ai": { "binding": "AI" }`) gains `env.AI.websearch({ gatewayId, query, provider, limit, byokAlias })`, which returns a standard `Response`.
Response: `{ items: [{ url, title, description, ... }], metadata: { query, requestId, latencyMs } }`.
Prerequisite: AI Gateway credits loaded, or a provider key stored on the gateway.
Source: https://developers.cloudflare.com/web-search/how-to-use/

```ts
const response = await env.AI.websearch({ gatewayId: "default", query: "...", provider: "exa", limit: 5 });
const results = await response.json();
```

BYOK: store a Ceramic.ai, Exa or Linkup key under the gateway's Provider Keys with an alias (keys are encrypted with Secrets Store); with `byokAlias` set the request fails with 400 if the key is missing instead of falling back to credits; without it, a key aliased `default` is used if present, otherwise credits.
Tool use: the docs show a `web_search` function tool on `@cf/google/gemma-4-26b-a4b-it` via `env.AI.run(..., { gateway: { id: "default" } })`, running `env.AI.websearch()` when the model calls it and feeding results back as a `tool` message.
Source: https://developers.cloudflare.com/web-search/how-to-use/

## AI Crawl Control

### What it is

AI Crawl Control (formerly AI Audit) shows which AI services access a zone's content and lets the owner allow, block or charge them.
Its features are: monitoring crawler activity, granular per-crawler allow and block policies, `robots.txt` compliance tracking with enforcement rules, monetization through Pay Per Crawl, and zero-configuration deployment on all plans.
It needs a domain on Cloudflare with proxied traffic, and lives in the dashboard under each zone at `/:zone/ai`.
Sources: https://developers.cloudflare.com/ai-crawl-control/, https://developers.cloudflare.com/ai-crawl-control/get-started/

### Status (as of 2026-10-05)

- AI Crawl Control itself is "Available on all plans".
- Pay Per Crawl is described as "private beta" on the overview and in the changelog, and as "closed beta" on the Pay Per Crawl pages; signup is at https://www.cloudflare.com/paypercrawl-signup/ or through an Enterprise account executive.
- The plan comparison table lists the ability to charge crawlers only under "Enterprise plans with Bot Management".

Sources: https://developers.cloudflare.com/ai-crawl-control/, https://developers.cloudflare.com/ai-crawl-control/features/pay-per-crawl/what-is-pay-per-crawl/, https://developers.cloudflare.com/ai-crawl-control/get-started/

### Key concepts

- Detection: all plans identify AI crawlers by user agent string, while Enterprise plans with Bot Management use Bot Management detection IDs.
  Free plans see a 24-hour analytics window; Enterprise gets configurable timeframes.
- Crawler, operator and category: an operator (OpenAI, Microsoft, Google, ByteDance, Anthropic, Meta and others) runs several crawlers, and each crawler has one category ("AI Crawler", "AI Search", "AI Assistant" or "Search Engine").
  The bot reference lists 32 crawlers with detection IDs and user agents, for example GPTBot `123815556`/`33563875`, ChatGPT-User, OAI-SearchBot and ClaudeBot `33563859`.
- Actions per crawler: Allow, Block, or (with Pay Per Crawl) Charge; bulk actions are available.
  Blocking or charging Search Engine crawlers can hurt SEO.
- Tabs: Overview (executive summary, managed robots.txt status, referrals on paid plans, crawlers grouped by operator), Crawlers, Metrics, and Robots.txt or Directives (availability, Content Signals detection, violations by crawler, path and directive, and an Agent Readiness check covering robots.txt, Markdown for Agents and Content Signals Policy).
- Custom block responses (paid plans, since 2025-08-27) can return HTTP 402 to blocked crawlers; Transform Rules can add a `Link: <...>; rel="license"` header with licensing terms.
- Redirects for AI Training (since 2026-04-17) redirect AI training crawlers to canonical URLs; available on Pro, Business and Enterprise at no extra cost.
- An AI Crawl Control Read Only role exists (since 2026-01-13), and GraphQL Analytics exposes the data.

Sources: https://developers.cloudflare.com/ai-crawl-control/features/manage-ai-crawlers/, https://developers.cloudflare.com/ai-crawl-control/features/analyze-ai-traffic/, https://developers.cloudflare.com/ai-crawl-control/features/track-robots-txt/, https://developers.cloudflare.com/ai-crawl-control/reference/bots/, https://developers.cloudflare.com/ai-crawl-control/reference/glossary/, https://developers.cloudflare.com/ai-crawl-control/changelog/, https://developers.cloudflare.com/ai-crawl-control/reference/redirects-for-ai-training/, https://developers.cloudflare.com/ai-crawl-control/configuration/ai-crawl-control-with-transform-rules/

### Pay Per Crawl

Pay Per Crawl lets a site owner set a price per zone; each crawler request either presents payment intent in headers and gets HTTP 200, or gets HTTP 402 with the price.
Cloudflare is the Merchant of Record and runs the infrastructure.
WAF or Bot Management blocks override the "charge" action.
Source: https://developers.cloudflare.com/ai-crawl-control/features/pay-per-crawl/what-is-pay-per-crawl/

Payment rail: Pay Per Crawl uses Stripe and US dollars, not x402 or stablecoins.
Crawler operators connect a Stripe account, invoices are created and managed in Stripe, and crawlers must enforce their own spending limits ("Cloudflare is not responsible for configuring spending limits").
Publishers must create a dedicated Cloudflare Stripe Connect account (pre-existing Stripe accounts do not work) and are paid monthly, subject to settlement periods and minimum payout thresholds; the accrued balance is not visible in the dashboard.
Sources: https://developers.cloudflare.com/ai-crawl-control/features/pay-per-crawl/use-pay-per-crawl-as-ai-owner/connect-to-stripe/, https://developers.cloudflare.com/ai-crawl-control/features/pay-per-crawl/use-pay-per-crawl-as-site-owner/manage-payouts/

Crawler flow:

1. Set up a Cloudflare account, then verify the crawler: implement Web Bot Auth, follow the verified bots policy, and submit the Bot Submission Form (type Verified Bot or Signed Agent, verification method Request Signature).
2. Discover payable zones with `GET https://crawlers-api.ai-audit.cfdata.org/charged_zones?limit=50` (cursor pagination), signed with Web Bot Auth `Signature`, `Signature-Input` and `Signature-Agent` headers; it returns only zones that chose to charge your crawler.
3. Request a page; a paywalled response is `HTTP/2 402` with `crawler-price: USD 0.01`.
4. Retry with either `crawler-exact-price` (must equal `crawler-price`) or `crawler-max-price` (pay anything up to it); the payment header must be included in the signed `signature-input` components.
5. Success is `HTTP 200` with `crawler-charged: USD 0.01`, which you should log; failures carry a `crawler-error` header.

Sources: https://developers.cloudflare.com/ai-crawl-control/features/pay-per-crawl/use-pay-per-crawl-as-ai-owner/verify-ai-crawler/, https://developers.cloudflare.com/ai-crawl-control/features/pay-per-crawl/use-pay-per-crawl-as-ai-owner/discover-payable-content/, https://developers.cloudflare.com/ai-crawl-control/features/pay-per-crawl/use-pay-per-crawl-as-ai-owner/crawl-pages/

Error codes: `CrawlerForbidden` (403), `StrongAuthRequired` (400), `InvalidSignature` (400), `InvalidCrawlerPriceValue` (400), `MissingCrawlerPrice` (402), `PaymentFailed` (403), `InvalidCrawlerExactPrice` (402), `InvalidCrawlerMaxPrice` (402), `ConflictingPriceHeaders` (400), `InvalidContentPrice` (502) and `InternalError` (500).
Source: https://developers.cloudflare.com/ai-crawl-control/features/pay-per-crawl/use-pay-per-crawl-as-ai-owner/error-codes/

Billing rules: only successful responses are charged; re-crawls are charged every time; `/robots.txt`, `/sitemap.xml`, `/security.txt`, `/.well-known/security.txt` and `/crawlers.json` are always free; one price applies to all crawlers set to Charge.
Source: https://developers.cloudflare.com/ai-crawl-control/features/pay-per-crawl/faq/

Site owner setup:

1. An Administrator or Super Administrator sets domains to Visible under Manage Account > Settings > Pay Per Crawl (the domain must use Cloudflare nameservers or Cloudflare-managed DNS).
2. In the zone's AI Crawl Control Payments tab, enable Pay Per Crawl and set a default price; the minimum is $0.001 USD per crawl (as of 2026-10-05).
3. Choose Charge, Allow or Block per crawler in the Security tab.
4. Monitor activity and connect Stripe for payouts.

Sources: https://developers.cloudflare.com/ai-crawl-control/features/pay-per-crawl/use-pay-per-crawl-as-site-owner/enable-in-account-settings/, https://developers.cloudflare.com/ai-crawl-control/features/pay-per-crawl/use-pay-per-crawl-as-site-owner/set-a-pay-per-crawl-price/, https://developers.cloudflare.com/ai-crawl-control/features/pay-per-crawl/use-pay-per-crawl-as-site-owner/select-crawlers-to-charge/

Advanced configuration (since 2026-06-16):

- Configuration Rules with the action "Disable Pay Per Crawl" make URI patterns free.
- Dynamic pricing: enable it, then have the origin or a Worker return `crawler-price: USD 3.14` per response.
- Cloudflare sends `cf-pay-per-crawl: protocol=cloudflare, pricing=<zone-default | in-band | bypass>` to the origin so it knows whether to price the request.
- `crawler-price` is forwarded to the client only on a 402.
- Snippets can read `cf-pay-per-crawl` but cannot set prices.

Source: https://developers.cloudflare.com/ai-crawl-control/features/pay-per-crawl/use-pay-per-crawl-as-site-owner/advanced-configuration/

Link to x402: Cloudflare's 2025 x402 blog proposed a `deferred` x402 scheme (signed commitment now, batched settlement later, on card, bank or stablecoin rails) and said it would bring it to Pay Per Crawl; the mirrored Pay Per Crawl docs still describe only the `crawler-*` headers and Stripe.
For x402-based charging today, the AI Crawl Control "Worker templates" page offers the x402-proxy template (bot-score gating, wallet payout on Base) as an alternative.
Sources: https://blog.cloudflare.com/x402/, https://developers.cloudflare.com/ai-crawl-control/reference/worker-templates/, https://developers.cloudflare.com/agents/tools/payments/x402/charge-for-http-content/

## Agent Lee (not in the sidebar)

### What it is

Agent Lee is an AI co-pilot built into the Cloudflare dashboard (the **Ask AI** button, `Cmd`/`Ctrl` + `/`, or `t` then `a`); it was previously called Cloudflare Agent.
It answers from your live account data (zone config, DNS records, security settings, plan entitlements), makes changes (DNS records, zone settings, security rules) only after explicit approval, can undo its own earlier changes as a proposed inverse write, runs diagnostics (DNS lookups, TLS certificate checks, WHOIS and RDAP), builds charts from account analytics, navigates the dashboard by searching its page index, lists and summarizes past conversations, prepares support cases for eligible accounts, and grounds product answers in the developer docs and changelog.
Source: https://developers.cloudflare.com/agent-lee/

### Status (as of 2026-10-05)

Beta, available to accounts on a Free plan and to select Enterprise customers (Enterprise access through the account team); not available in the FedRAMP environment; rollout is still in progress.
Sources: https://developers.cloudflare.com/agent-lee/, https://developers.cloudflare.com/agent-lee/manage-access/ (last updated Sep 24, 2026)

### Key facts

- Access: it can read zone settings, DNS, firewall and WAF rules, Workers scripts, routes and bindings, R2 bucket names, Tunnel config, cache rules, Registrar data and plan and usage metadata; it cannot access payment methods, billing history, credentials, API tokens, raw logs or Logpush, or other accounts.
- Permissions: it acts through an API token it creates for you, named `Cloudflare Agent Token -` plus a date (visible under My Profile > API Tokens), with templates Full access, Read only or Custom; it can never write account settings, membership, billing or API tokens; admins can force "Write off".
- Storage: conversations are stored per user in Durable Objects and retained for one year from the last message; data is not used for training.
- Limitations: no deploying or running code, no multi-account sessions, no unapproved writes.
- Built on Cloudflare: Agents SDK (lifecycle, state, scheduling), Durable Objects (conversation storage and the write approval gate), Workers AI (inference), AI Gateway (routing, logging, analytics) and the Cloudflare MCP server (tool definitions for API operations).
- Code export: generated starter projects export to a temporary Git repository in Cloudflare-managed storage that expires about 36 hours after creation, via a one-time clone command with a read credential valid about one hour; limits are 50 files, 100 KB per file and 2 MB total.

Sources: https://developers.cloudflare.com/agent-lee/, https://developers.cloudflare.com/agent-lee/manage-access/, https://developers.cloudflare.com/agent-lee/take-home-code/

### Trading agents

- One Agent (a Durable Object) per strategy, wallet or user, addressed by name, with positions and fills in its SQL state, `schedule` or `scheduleEvery` for polling, WebSockets to the UI, and Workflows for multi-step execution with durable retries (see [Agents](#agents)).
- Human-in-the-loop approval (`needsApproval` in chat agents, Think Actions with approval risk, `onPaymentRequired` for x402) before any signing step, which the payments pages themselves recommend for spending.
- Model choice: the hosted tool-calling and reasoning models with long context (`@cf/zai-org/glm-5.3`, `@cf/deepseek-ai/deepseek-v4-pro-0813`, `@cf/moonshotai/kimi-k2.7-code`, `@cf/openai/gpt-oss-120b`) or frontier third-party models through the same `env.AI.run()`.
  Clef decision models return calibrated probabilities for typed questions, which could gate trades or flag risky tokens (inference; see [Workers AI](#workers-ai)).
- Cost control: AI Gateway spend limits can be split by request metadata such as an agent id, with caching, fallbacks and logs for every model call (see [AI Gateway](#ai-gateway)).
- Keys: store signing keys and RPC keys as Worker secrets; never put them inside a Sandbox.

- Backtests and quant scripts: run Python in a Linux sandbox with `enableInternet: false`, market data mounted from R2, and results returned to the agent.
- News and sentiment: the Web Search API from inside the agent (Ceramic.ai at $0.25 per 1,000 requests is the cheapest provider).

### Workers AI

- **Pricing lists models that no longer exist in the catalog.** The pricing page (updated 2026-10-01) still prices `@cf/meta/llama-3.1-8b-instruct`, `@cf/meta/llama-3-8b-instruct`, `@cf/meta/llama-3-8b-instruct-awq`, `@cf/meta/llama-2-7b-chat-fp16`, `@cf/mistral/mistral-7b-instruct-v0.1`, `@cf/google/gemma-3-12b-it` and `@cf/moonshotai/kimi-k2.5`, all deprecated on 2026-05-30 per the changelog, and also prices `@cf/meta/llama-3.1-8b-instruct-fp8-fast`, `@cf/meta/llama-3.1-70b-instruct-fp8-fast` and `@cf/meta/llama-3.1-8b-instruct-awq`, which have no model page in the catalog (https://developers.cloudflare.com/workers-ai/platform/pricing/ versus https://developers.cloudflare.com/workers-ai/changelog/ and https://developers.cloudflare.com/workers-ai/models/).
- **Official examples use deprecated models.** The REST get-started, bindings reference, OpenAI-compatibility page and AI Gateway Workers AI page use `@cf/meta/llama-3.1-8b-instruct`; the AI SDK page uses `@cf/meta/llama-2-7b-chat-int8`; all function-calling pages use `@hf/nousresearch/hermes-2-pro-mistral-7b`; the RAG tutorial uses `@cf/meta/llama-3-8b-instruct`; the prompt-caching page and AI Gateway binding page use `@cf/moonshotai/kimi-k2.5`; all of these were deprecated or aliased on 2026-05-30.
- **JSON Mode's supported-model list is stale.** Four of its six models (`llama-3-8b-instruct`, `llama-3.1-8b-instruct`, `hermes-2-pro-mistral-7b`, `deepseek-coder-6.7b-instruct-awq`) are deprecated, the last since 2025-10-01, and no current frontier model is listed although their pages advertise structured outputs (https://developers.cloudflare.com/workers-ai/features/json-mode/).
- **Public LoRAs target only deprecated bases.** All three `cf-public-*` adapters list compatibility only with `@cf/mistral/mistral-7b-instruct-v0.1` and `@hf/mistral/mistral-7b-instruct-v0.2`, both deprecated 2026-05-30 (https://developers.cloudflare.com/workers-ai/features/fine-tunes/public-loras/).
- **LoRA file names disagree.** The errors page says a fine-tune needs `model.safetensors` and `config.json` (error 3039), while the LoRA page requires exactly `adapter_model.safetensors` and `adapter_config.json` (https://developers.cloudflare.com/workers-ai/platform/errors/ versus https://developers.cloudflare.com/workers-ai/features/fine-tunes/loras/).
- **LoRA rank limit is ambiguous.** The page says "Adapter must be trained with rank `r <=8` as well as larger ranks if up to 32", which does not state a single maximum (https://developers.cloudflare.com/workers-ai/features/fine-tunes/loras/).
- **LoRA model id spelling varies.** The same page uses both `@cf/mistral/mistral-7b-instruct-v0.2-lora` and `@cf/mistralai/mistral-7b-instruct-v0.2-lora`; the catalog page id is `@cf/mistral/mistral-7b-instruct-v0.2-lora`.
- **Limits page names a model with no catalog page.** It gives `@cf/runwayml/stable-diffusion-v1-5-img2img` its own 1500 requests per minute, but only `stable-diffusion-v1-5-inpainting` is in the catalog (https://developers.cloudflare.com/workers-ai/platform/limits/).
- **Model counts disagree.** The overview says "50+ open-source models", the Workers AI catalog shows 69 (including non-open partner models from Deepgram and Leonardo), and the unified catalog shows 233, all as of 2026-10-05.
- **Neurons messaging is mixed.** The 2024-09-26 changelog said "No more neurons", while the current pricing page says billing still happens in neurons behind per-unit prices.

- **Product changelog lags.** The Workers AI product changelog's newest entry is 2026-06-16, while the global changelog has later Workers AI posts (Unified Billing 2026-08-07, DeepSeek V4 2026-08-14, Qwen 3.8 2026-08-17, GLM-5.3 2026-08-26 and 2026-08-28, Clef 2026-10-01).

- **Hugging Face Chat UI page is narrow.** It says it works with models "that begin with the `@hf` parameter", but most surviving `@hf` models were deprecated, and its example uses the deprecated `hermes-2-pro-mistral-7b`.
- **Missing pages.** There is no data-center, region or jurisdiction-selection page for Workers AI, and no request body size or timeout numbers beyond error codes 3006 and 3007, as of 2026-10-05.
